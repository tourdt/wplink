# 织里服装地图产品需求文档

版本：v1.2

日期：2026-10-09  
状态：首发目标版本，供产品、开发、测试和运营评审；不代表功能已实现  
产品工作名称：织里服装地图，正式名称另行确定  
首发区域：织里  
交付基础：现有 `wxapp`、Go/go-zero 后端和管理后台

首发以“找到合适的档口、查看主页、导航到店”为主，同时兼容加工厂、房东和配套服务者建立业务主页。商家自主填写主营和位置，采购者通过列表搜索和筛选找到商家。后续在同一商家主页下增加商品展示、资源发布和服务信息，沿用现有账号、商家身份与资源体系。

## 1 产品目标与范围依据

### 1.1 已确定方向

- 在当前 wxapp 上改造，不新建第二套小程序代码工程。
- 首发聚焦服装地图，暂不上线供需发布及其他独立业务模块。
- 商家能自主提交主营、地址、地图坐标和店铺主页资料。
- 用户能通过档口列表进入主页，并使用第三方地图导航。
- 后续增加资源发布，商品和服务能通过店铺主页被发现。
- 保留项目扩展能力，但不为未来业务提前建设交易、库存或复杂平台框架。

### 1.2 本版采用的产品默认规则

以下规则用于形成可实施的完整需求，可在实施评审时调整：

- 首页默认列表；地图用于单店定位和导航，全区域地图浏览不是首发阻塞项。
- 入驻免费，首发不使用 VIP、发布额度或付费解锁限制找店。
- 基础资料与内容校验通过后公开；不设置每家店都必须人工审核的前置流程，异常资料进入人工处理。
- 公开业务电话、微信由商家主动选择；默认不公开，也不直接公开登录手机号。
- 首发沿用现有一个主要经营主体的管理方式；主体可有主要业务和多项兼营业务、一个可选的公开接待地点。账号、主体和资源通过主体 ID 关联。

### 1.3 文档关系

本文件定义新的目标产品范围，[首发验收清单](apparel-map-mvp-acceptance.md)定义交付判断标准。旧[平台 PRD](apparel-industry-platform-prd.md)继续作为历史归档，[原 MVP 验收清单](mvp-acceptance-checklist.md)用于追溯原版本，不能据其要求首发同时开放资源发布。

运行时代码、`backend/app/api/` 和 `backend/migrations/` 仍是已实现接口与数据结构的事实来源；[技术架构文档](technical-architecture.md)用于理解现有系统。本 PRD 中的状态名称和能力划分是产品语义，不直接指定数据库字段、接口路径或迁移方案。

## 2 用户与核心价值

| 用户 | 主要目标 | 首发交付价值 |
|---|---|---|
| 采购者、零售店主、电商从业者 | 按主营找到档口，到店看货 | 可搜索、可筛选、位置清楚、可导航 |
| 档口经营者 | 让客户找到自己，减少重复介绍地址 | 可维护、可分享的业务主页 |
| 加工厂、货源供应方 | 展示经营品类、加工能力与接待地点 | 同一主体可兼营多种业务 |
| 房东、配套服务者 | 展示出租类型或服务项目与服务区域 | 无 GPS 也能完成入驻并分享主页 |
| 平台运营 | 增加真实商家，维护资料质量 | 查看入驻、处理异常、纠错和上下架 |

首发验证的是“真实档口信息能否帮助用户找店”，不以注册人数或地图点位总数代替业务效果。导航点击代表到店意向，不代表实际到店或成交。

## 3 阶段划分

| 阶段 | 对外开放 | 进入下一阶段的依据 |
|---|---|---|
| 第一阶段 服装地图 | 入驻、列表、主营筛选、主页、位置、导航、分享、基础治理 | 目标区域有可用商家覆盖，用户产生找店行为，商家愿意维护资料 |
| 第二阶段 资源发布 | 我的发布、发布及编辑、审核、资源列表与详情、店铺内资源展示 | 商家有持续发布意愿，采购者明确需要查看具体货品或供需 |
| 第三阶段 服务与区域扩展 | 按需开放服务类资源、更多资源类型、其他产业带 | 已有发布流程可运营，分类与治理规则适用新范围 |

第二阶段优先选择少量已验证需求的资源类型，不一次开放全部历史类型。在线交易、订单、支付、库存、担保、即时聊天及复杂营销不属于以上阶段的默认承诺。

## 4 首发功能边界

### 4.1 必须交付

- 找档口：列表、关键词搜索、统一主营分类、分页、空态和失败重试。
- 店铺主页：名称、主营、简介、图片、详细地址、可用导航、分享。
- 入驻与管理：登录、保存草稿、提交入驻、修改资料、查看公开状态、暂停展示。
- 位置：自主选点、地址补充、有效性校验、位置纠错、异常位置处理。
- 联系：商家主动公开的业务电话或微信；未公开时不返回、不展示。
- 管理后台：商家查询、异常处理、隐藏与恢复、分类维护、操作记录。
- 运营数据：入驻转化、主页访问、导航意向、联系行为和位置反馈。

### 4.2 首发不开放

资源发布、供需市场、商品管理、服务发布、招聘租赁、VIP 与权益购买、付费置顶、联系付费解锁、独立消息中心、平台内成交流程。

首发主页中的展示照片不是商品列表，不提供商品价格、库存、购买按钮或订单。现有收藏关注能力可保留为后续增强项，不作为核心闭环上线的前提。

## 5 页面与导航

### 5.1 底部入口

| 入口 | 内容 |
|---|---|
| 找档口 | 默认首页，搜索、主营筛选、档口列表、免费入驻入口 |
| 我的 | 未登录引导、入驻或管理店铺、预览主页、展示状态、账号与隐私 |

不展示未上线栏目、空的商品区或不可使用的“发布”按钮。以后开放资源发布时，再增加发布和资源浏览入口，不更换已有商家主页标识。

### 5.2 页面关系

采购者：找档口 → 店铺主页 → 店铺位置 → 第三方地图导航。主页也可直接发起导航。

商家：免费入驻 → 必要时登录 → 选择主要和兼营业务 → 填写对应资料，按需开启地图 → 提交 → 查看结果 → 预览并分享主页。

运营：商家管理 → 查看资料与位置反馈 → 核实 → 修正展示状态 → 留存处理原因。

浏览、搜索、查看主页和导航不要求登录。编辑店铺、提交纠错需要登录；登录完成后返回原操作，不丢失已填写内容。首次登录产生的默认商家记录，不等于已经公开入驻。

## 6 档口列表与搜索

### 6.1 展示资格

公开目录只包含：经营主体可用、已完成入驻、主页公开且主动开启地图展示、位置有效且未被隐藏的商家。首发不混入虚构数据、演示点位或未确认归属的待认领档口。

已有平台预录点位可留作后台辅助资料；经商家确认并关联有效入驻商家后，才能以该店铺身份进入目录。无需商家先找到一个预录点位才能入驻。

列表卡片包含名称、封面或统一占位图、业务身份和适用的主营标签、市场或详细地址摘要，点击进入主页。距离仅在用户允许获取定位且计算有效时展示，并标注为直线距离，不当作路线距离。

### 6.2 搜索与筛选

- 当前关键词覆盖名称、市场、楼栋、楼层和档口号；主营通过分类筛选，不把尚未实现的关键词能力写入搜索提示。
- 分类来自后台统一字典；商家选择、筛选请求与结果展示使用一致编码。
- 主营允许多选，并保留补充描述；自由文本不能代替结构化分类。
- 首发分类以织里服装经营为范围，具体类目由运营维护，不把历史招聘、租赁类别直接显示为服装主营。
- 多个主营类别采用“符合任一所选类别”；关键词与类别条件同时生效。
- 默认采用可解释的稳定排序，同等条件有固定次序；不以未上线的 VIP 或资源发布量决定排名。
- 搜索、筛选切换后重置分页；连续加载不能重复、遗漏同一查询快照中的结果。

首发服务区域由站点配置明确；不要求采购者身处织里才能搜索。不授权当前位置仍可查找织里档口，不出现强制定位弹窗循环。

### 6.3 空态与错误

- 尚无入驻：展示“首批档口入驻中”和免费入驻入口，不显示虚假商家。
- 搜索无结果：保留搜索条件，提示更换关键词或清除筛选。
- 网络失败：明确加载失败，允许重试，不能伪装成零商家。
- 店铺已暂停或被隐藏：历史分享链接显示当前不可公开访问，不泄露联系方式，不跳转到其他店铺。

## 7 商家入驻与资料

### 7.1 字段要求

| 字段 | 提交入驻要求 | 说明 |
|---|---|---|
| 主体名称 | 必填 | 对外展示名称，按业务提示店铺、工厂或出租方名称 |
| 主体性质 | 必填 | 个人或企业 / 机构，自填性质不代表认证 |
| 主要业务与兼营业务 | 至少一项 | 档口、加工厂、房东 / 出租方、配套服务、货源供应；主要业务必须在已选身份中 |
| 经营品类 | 按身份必填 | 档口、加工厂、货源供应方至少一项；房东和纯服务者不强制选择服装品类 |
| 加工工艺 / 出租类型 / 服务项目 | 按身份必填 | 对应已选业务，兼营身份也填写所需信息 |
| 简介、业务实拍、Logo | 选填 | 不把有门头照片作为所有业务主体的入驻前提 |
| 服务区域 | 选填 | 展示服务覆盖区域，不生成虚构地图坐标 |
| 详细接待地址和地图位置 | 开启地图展示时必填 | 房东不要求公开个人住址；出租房源地址以后归属具体资源 |
| 业务电话与微信 | 选填 | 明确选择公开后才返回访客；不自动公开登录手机号 |

资料完整性、主页公开和地图展示分别判断。无 GPS 主体可以完成入驻并分享主页，但不会进入公开地点目录。地图关闭不清除管理者已保存的私有位置，访客不能读取精确地址、坐标或内部楼栋档口信息。新主体默认关闭地图展示；后续保存由用户明确选择地图开关。

业务身份决定资料要求与展示方式，不直接授予发布权限、认证标签或额外管理权限。保存必须提交完整业务档案与地图开关，不推断旧身份，不提供历史数据或旧客户端适配。新账号从未完善档案开始。

### 7.2 入驻结果

正常流程为：草稿 → 提交校验 → 已公开。内容校验尚未完成时显示处理中，校验不通过时显示需修改及原因，不能提前承诺已公开。

首发采用自主入驻和异常治理。若内容服务判断异常、发生重复归属争议或人工隐藏，则进入待处理，不因再次点击保存自动解除平台限制。日常资料校验通过不等同于真实性认证，不展示未经核实的认证标签。

重复提交沿用同一个商家和位置关联，不新建重复店铺。重复店名或相近坐标仅作为核查线索，不能自动合并或转移店铺归属。

### 7.3 修改与公开

- 普通资料修改校验通过后对外生效；校验未完成或失败时不公开新的内容。
- 修改详细地址或清除位置后，旧坐标不能继续用于导航。重新选点并通过校验前，该店退出目录，主页提示位置待完善。
- 修改位置、分类或展示状态后，列表、主页和导航使用同一份已生效数据。
- 经营者可暂停整个主页，暂停后退出目录且访客无法查看主页。也可单独关闭地图，主页及授权联系仍可公开；重新开启地图需核对地址与位置。
- 普通业务编辑使用“保留地点”，不改位置状态或结案反馈；只使用v2结构草稿，恢复不能覆盖服务端最新位置风险基线。只有明确重新选点才按原规则更新位置。
- 商家注销或停用后，公开访问随主体状态收敛；保留必要管理记录，不通过删除重建规避状态限制。

## 8 店铺主页与第三方导航

### 8.1 首发主页

展示顺序为：主体名称与封面 → 主要和兼营身份 → 对应业务内容 → 简介与实拍 → 服务区域 → 获准公开的接待地址。只有公开有效地点提供导航；联系方式按独立授权展示。支持分享同一主体主页。

主页不依赖商家发布过资源才能成立，不展示“发布数量为零”、供需空列表、资源曝光热度或 VIP 引导。没有公开电话、微信时隐藏对应按钮，导航仍可使用。

### 8.2 位置体验

- 地图用于确认档口位置，不承担路线规划和导航算法。
- 接入当前小程序可用的第三方位置与导航能力，首发无需自建导航。
- 导航目标为商家已经生效的位置；传递坐标时确保来源和目标服务坐标系一致。
- 地址、楼层、档口号在导航前清晰可见，地图坐标不替代室内找店信息。
- 坐标无效、被撤回或存在未解除的位置风险时，禁用导航并给出原因。
- 地图调起失败时保留地址复制入口和重试入口，不记录为已到店。
- 现有附近商家能力可以复用，但首发不以附近推荐作为必要条件；附近加载失败不影响当前商家导航。

### 8.3 位置纠错

登录用户可反馈位置不准或店铺不存在，并查看提交结果。后台可核查、标记位置待确认、隐藏位置或恢复展示，所有处置有原因和记录。

用户反馈本身不直接覆盖商家坐标。首发默认不因简单累计报告次数自动处罚店铺；如要启用自动隐藏阈值，应另行明确去重、核实、恢复和防误报规则。平台人工限制不得由商家普通资料保存解除。

## 9 运营后台与冷启动

后台围绕店铺运营提供：按站点、主营、入驻状态和展示状态检索；查看原始资料和有效位置；处理异常内容、重复归属及位置报告；隐藏和恢复；维护主营分类；查看操作日志。

分类停用后不能新增选择；现有店铺保留原记录并提示商家调整，不因字典变化静默删除其主营。首发无需新建独立后台系统。

冷启动先聚焦一个市场、街区或主营类别，邀请首批商家完善资料。运营可以协助填写，但必须由商家确认内容及公开联系方式选择，不代替商家授权。商家提交的真实资料公开后，可分享店铺名片给客户。

允许数据库从空数据启动。先开展商家招募，再根据区域覆盖和采购者反馈扩大推广；不把“发布一个空列表后自然增长”作为唯一获客方案，不承诺固定客源或成交量。

## 10 资源发布的扩展原则

### 10.1 保留现有核心关系

| 对象 | 首发职责 | 后续扩展 |
|---|---|---|
| 用户 | 登录、管理自己有权限的商家 | 发布操作、消息、收藏等沿用同一账号 |
| 商家 | 长期经营主体、主页与主营 | 作为资源归属主体，原 ID 和分享入口不变 |
| 经营位置 | 地图展示与导航 | 可支持更多位置，但首发不建设多门店管理 |
| 资源 | 暂不对外开放，保留现有数据与模块 | 承载商品供应、需求和服务等信息 |
| 城市站 | 织里范围与分类配置 | 在需求成立时增加产业带，不复制一套系统 |

位置是商家的位置能力，不能成为资源发布的唯一身份。后续合理存在没有线下档口的服务商；其资源是否可发布由对应阶段规则决定，不要求为了发布资源伪造地图位置。

### 10.2 统一资源模型

后续资源发布优先复用现有 `resources`、`resource_type_configs` 及发布、审核、展示和生命周期能力。资源归属沿用 `merchantId`，按现有 `direction` 区分供应与需求，按 `typeCode` 区分业务类型。

商品展示首先作为货源类资源评估，服务作为服务类资源评估；新类型编码、字段模板、有效期和审核规则在第二阶段确定，不能直接复制历史 PRD 的编码作为已实现契约。

商品展示不默认包含 SKU、库存、购物车、订单和支付。仅当后续明确需要交易和履约时，才单独设计相应业务。

### 10.3 主页扩展方式

第一阶段主页显示店铺信息；第二阶段在同一主页增加已发布资源区，可按实际开放类型展示商品、供应或服务。未开放类型和没有公开内容的栏目不展示。

资源详情可以回到所属商家主页；用户从商家列表进入主页后可以发现其资源。店铺资料与资源内容分别维护：修改店名不重建资源，资源下架不删除店铺，店铺暂停时按统一公开规则屏蔽关联资源。

店铺业务联系方式与单条资源联系方式分别定义公开范围，不能因某条资源公开了电话，就推定商家所有联系方式允许公开。

### 10.4 首发就应保留的边界

- 保留资源模块及资源与主体的归属模型，作为后续发布功能基础；不实施历史数据迁移适配。
- 不强制入驻商家先发布一条资源，不让地图功能依赖发布额度或资源审核状态。
- 资源未开放时，前端无入口，后端也拒绝该首发站点普通用户的新发布及相关商业操作；后台资源管理保留权限控制。
- 对旧资源链接给出明确的暂未开放状态，不能因隐藏菜单仍从深链接进入完整资源业务。
- 检查资源通知、自动推荐、推广和付费任务是否会触达首发用户；关闭不适用触达，保留必要的数据维护任务。
- 后续启用资源模块时，账号、商家、主页和位置不需要迁移到第二套系统。
- 不新建插件系统、通用工作流引擎、微服务拆分或第二套权限体系来实现这些预留。

## 11 现有项目的改造边界

以下为仓库检查结果与目标差异，不代表已完成改造。

| 部分 | 现有基础 | 首发目标改造 |
|---|---|---|
| 小程序导航 | 首页、拿货档口、发布、供需、我的 | 收缩为找档口和我的，清理旧入口与跳转依赖 |
| 档口列表 | 已有搜索、分类、分页和卡片 | 默认入口，仅展示满足首发资格的入驻店铺 |
| 商家资料 | 已有名称、主营、图片、地址、位置 | 入驻流程、统一分类、完整性与公开状态 |
| 店铺主页 | 当前包含公开供应和资源统计 | 独立店铺名片，资源区等待第二阶段开放 |
| 联系方式 | 当前公开商家详情不返回，仅管理者可编辑读取 | 增加主动公开选择和对应服务端返回规则 |
| 商家与地图 | 当前商家保存与地图点位列表分开 | 打通提交入驻到列表可见，修改同步、重复提交不重复建点 |
| 管理后台 | 已有商家和地图管理基础 | 服务首发店铺与位置异常治理 |

商家与地图的实现可以复用现有点位关联，也可以调整查询来源，但必须有明确的数据权威来源，避免两份地址和坐标独立修改。具体方案由实施设计确定，本 PRD 不要求先建新表或重写服务。

现有文档中部分位置治理规则与当前代码存在差异，实施前需以实际运行链路核对；不得把旧文档描述视为已经实现或把所有旧规则直接迁入首发版。

## 12 数据指标与验证

| 指标 | 定义与用途 |
|---|---|
| 入驻完成率 | 统计周期内发起入驻的去重商家中，完成公开入驻的比例 |
| 有效公开店铺数 | 满足目录资格的去重商家数，不含草稿、隐藏和演示资料 |
| 搜索无结果率 | 返回零条有效结果的成功搜索次数占比，不包含网络失败 |
| 主页访问 | 按商家与来源记录，区分列表、分享等入口 |
| 导航意向 | 用户点击导航及调起结果，不能宣称到店率 |
| 联系行为 | 电话按钮点击、微信复制等动作，不等同于联系成功 |
| 回访与维护 | 用户再次找店、商家主动更新资料的情况 |
| 位置质量 | 有效位置反馈、后台处理结果和重复反馈情况 |

首发先建立真实基线，再确定增长目标，不以虚构行业转化率设定验收阈值。按现有统计能力复用和补齐事件，后台应能查看基本结果；不要求上线复杂分析平台。日志与统计不得记录完整电话、微信或不必要的精确用户位置。

## 13 上线验收与后续决策

上线必须跑通：全新商家无需运营先建点 → 填写主营、实拍和地址 → 自主选点 → 校验后公开 → 搜索和筛选能找到 → 打开同一店铺主页 → 导航到正确位置。

还必须验证：地址变更清除旧导航、暂停展示与历史链接一致、公开联系方式选择生效、其他用户无法修改商家资料、旧资源入口确实未开放、主体 ID 与资源归属关系正确。

完整场景见[服装地图首发验收清单](apparel-map-mvp-acceptance.md)。本阶段不以资源发布、VIP、支付或全国站点全部可用作为上线条件。

上线后结合采购者访谈、实际导航意向和商家更新行为决定第二阶段资源类型、服务范围及商业化方式。正式品牌名、首批主营字典、运营服务区域边界在上线前落定，不影响复用现有项目的方向。
