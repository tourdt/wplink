# 衣货通 MVP 验收清单

> 范围说明：本清单保留原供需版本的验收场景，不代表服装地图首发范围或当前功能均已通过。2026-10-09 起，新的地图首发目标以[产品需求文档](apparel-map-mvp-prd.md)和[地图首发验收清单](apparel-map-mvp-acceptance.md)为准；原资源发布场景用于后续阶段参考。

## 1. 发布、审核、搜索、联系、指标

- 商家在小程序“我的”页保存商家 ID。
- 商家进入“发布”，填写供需信息标题、品类、数量、价格、联系人和电话。
- 提交后进入发布成功页，可跳转消息中心或我的发布。
- 运营在后台“供需信息审核”看到待审核供需信息。
- 运营通过审核后，供需信息进入公开搜索列表。
- 买家在小程序“搜索”输入关键词或选择供需类型，能看到供需信息卡片。
- 买家进入供需信息详情，能查看价格、数量、描述和商家资料。
- 买家点击复制微信、联系商家或进入商家主页，会触发联系行为记录。
- 商家在“我的发布”看到曝光、浏览、电话、微信等效果数据。

## 2. 搜索无结果空态

- 买家搜索不存在的关键词。
- 页面展示“暂未找到合适供需信息”空态。
- 页面可引导用户更换关键词、切换筛选条件或选择热门搜索词。
- 搜索无结果不进入独立需求流程，可引导用户更换条件或通过发布页发布需求方向供需信息。

## 3. 商家资料和权益

- 商家进入资料页，可维护名称、头像、展示图片、联系方式和地址。
- 商家可不选位置；此时仍能保存资料、展示商家主页并发布供需信息，但不进入拿货档口。
- 商家可自主选择织里腾讯地图位置，并核对市场、楼栋、楼层和档口号；保存后无需人工审核即可公开。
- 商家手工修改地址或点击清除位置后，旧坐标会被清除，导航入口消失。
- 保存后商家主页展示最新商家资料。
- 后台“权益发放”可对商家发放发布额度或刷新额度，并要求填写原因。
- 操作日志中能看到权益发放记录。

## 4. 我的发布和供需信息生命周期

- 商家在“我的发布”按状态筛选供需信息。
- 商家保存草稿后，可在“我的发布”筛选草稿并提交审核。
- 已发布供需信息可以刷新、置顶、标记成交、下架。
- 已过期或已成交供需信息可以“再发类似”生成草稿。
- 即将过期和已过期供需信息会产生消息提醒。
- 服务启动后的生命周期自动任务会按配置间隔执行。
- 生命周期任务执行后，过期供需信息状态变更为 `expired`。

## 5. 消息中心

- 消息中心支持全部、未读、已读切换。
- 供需信息审核通过、驳回、下架、即将过期、已过期能产生消息。
- 效果反馈能产生消息。
- 用户点击未读消息后，状态可更新为已读。

## 6. Banner、专题和 web-view

- 后台“Banner 专题”可新增或编辑 Banner 和专题配置。
- 首页能展示 active Banner。
- Banner 跳转专题时，能打开专题供需信息列表。
- Banner 跳转供需信息时，能打开供需信息详情。
- Banner 跳转商家时，能打开商家主页。
- Banner 跳转 web-view 时，先通过白名单校验，再打开活动页。
- 不在白名单的活动链接展示不可访问状态。

## 7. 独立需求流程已删除

- 小程序不展示独立“提交需求”和“我的需求”入口。
- 需求方向内容只通过“发布”页和“我的发布”承接。
- 运营后台只验收供需信息审核、供需信息管理和操作日志，不验收独立需求处理页面。
- 小程序消息中心不展示旧对接类消息标签或进度文案。
- 迁移、演示数据、API 契约和后台导航不得重新引入独立需求处理链路。

## 8. 数据和审计

- `backend/scripts/seed_demo_data.sql` 可在干净数据库上重复执行。
- 演示数据包含织里 `active + completed + visible` 真实商家与可搜索的市场、档口资料，可用于目录、位置页和后台异常治理联调。
- 后台“数据概览”展示待审核供需信息和今日联系。
- 后台“操作日志”可按对象类型、对象 ID、操作者 ID 查询。
- 敏感操作至少覆盖审核通过、驳回、下架、发放和撤销。

## 9. 收藏、关注和保存搜索

- 买家登录后在供需信息详情页可以收藏或取消收藏供需信息。
- 买家登录后在商家主页可以关注或取消关注商家。
- 搜索页可以保存当前关键词和供需类型筛选。
- “我的”页可进入“收藏关注”，查看收藏供需信息、关注商家和保存的搜索。
- 从保存的搜索进入搜索页时，会恢复关键词和供需类型筛选。

## 10. 织里拿货档口与位置治理

- 拿货档口默认展示商家列表，只包含商家 `active`、资料 `completed`、位置 `visible` 且坐标有效的真实入驻商家。
- 按商家名、市场、楼栋、档口号和主营品类搜索或筛选，分页结果稳定，空态与失败态可重试。
- 进入单商家位置页，能看到当前商家和 1000 米内最多 20 家附近商家，Marker 与商家列表联动。
- 点击导航可通过 `uni.openLocation` 打开腾讯位置；附近查询失败时，当前商家和导航仍可用。
- 三名不同的登录用户报告同一商家位置错误后，位置自动变为 `risk_hidden` 并立即退出目录。
- 商家重新选择有效位置后恢复 `visible`，旧 `pending` 报告结案但审计记录保留。
- 后台“商家管理”可按位置状态筛选，查看、处理位置报告，并人工隐藏或恢复位置；结果写入 `operation_logs`。

## 当前验收限制

- 完整端到端手工点击验收依赖可连接的 PostgreSQL、已启动的后端 HTTP server、管理后台和微信开发者工具。
- 若当前执行环境缺少数据库连接或微信开发者工具，只能完成 SQL 静态校验、后端单元测试、后台构建和小程序构建；数据库可连接时应运行 `go run ./scripts/verify_migrations.go -config etc/app.yaml` 验证 migration up/down 和演示数据导入。
- 正式运营验收还应检查 `RuntimeMode: production` 下关键配置完整、微信 `jscode2session` 可用、七牛图片上传可用，并确认微信公众平台已配置 request/uploadFile 合法域名；短信验证码和手机号绑定不纳入首发验收。
