# 小程序权益与次数购买闭环设计

## 目标

让商家在“我的”、发布和刷新三个高意图场景中，能看懂当前发布/刷新权益，并以最短路径补充对应次数。购买入口按额度紧急程度呈现，避免“我的”页变成持续推销页面。

## 范围

### 包含

1. 将“我的权益”卡改为稳定的权益入口，不再因没有成长活动而提示“暂无可领取权益”。
2. 在权益卡按余额状态展示购买入口：额度为零时使用主按钮，低余额时使用轻量入口，余额充足时保留弱入口。
3. 从权益卡进入 VIP 页面时支持直接打开“购买次数”标签，并预选或突出发布次数包、刷新次数包。
4. 发布或刷新被 `quota_not_enough` 拦截时，展示说明和“立即购买”操作，跳转到相应次数包。
5. VIP 促销标签只采用服务端返回的有效 `saleLabel`，不再按套餐代码固定显示“限时特价”。
6. 微信支付成功返回后刷新当前权益与相关列表；在权益尚未到账时使用“支付已完成，权益到账后会自动更新”的准确提示。
7. 增加覆盖上述路径的前端源码行为测试。

### 不包含

1. 不新增套餐、次数包规格或变更现有价格。
2. 不改变权益扣减、订单创建、支付回调或权益发放的后端数据模型。
3. 不新增订单详情页、订单状态查询接口或支付轮询机制。
4. 不改变成长任务、置顶服务和商家资料完善的既有规则。

## 体验与交互

### 我的权益卡

权益卡继续展示发布次数、刷新次数和最近到期提醒，并始终可进入权益购买页。

| 余额状态 | 卡片操作 | 目的 |
| --- | --- | --- |
| 发布或刷新为 0 | 在相应额度块下展示“购买发布次数”或“购买刷新次数”主操作 | 消除无法继续经营时的路径障碍 |
| 发布或刷新为 1–2 次 | 展示“即将用完 · 去补充”轻入口 | 让用户提前补充但不造成打扰 |
| 两项均大于 2 次 | 展示“权益明细 / 加购次数”弱入口 | 保持权益可管理，不抢占页面主任务 |

成长活动存在时，权益页仍可继续呈现“免费获得”任务；付费购买和免费任务使用不同的文案与入口，不混淆为同一种权益来源。

### 购买页

保留现有 VIP 和“购买次数”双标签。在路由中增加可选 `quotaType` 参数：

- `publish_quota`：打开“购买次数”，突出发布次数包。
- `refresh_quota`：打开“购买次数”，突出刷新次数包。
- 参数缺失：保持当前 VIP 默认页。

突出仅改变首个可见商品和购买页说明，不改变后台配置的商品排序与价格。

### 额度不足

发布或刷新接口返回额度不足时，前端不只显示后端文本，而是弹出统一的购买引导：

- 发布：说明“发布次数已用完”，主按钮“购买发布次数”。
- 刷新：说明“刷新次数已用完”，主按钮“购买刷新次数”。
- 取消后保留当前填写内容或列表状态，不重复提交、不自动创建订单。

## 实现边界

### 小程序页面

- `pages/my/index.vue` 负责汇总权益、判断低余额状态及打开带参数的购买页。
- `pages/vip/index.vue` 负责解析 `tab` 与 `quotaType`，按真实促销字段展示标签，并在支付返回后重新获取商品数据。它不承担权益余额查询。
- `pages/publish/edit.vue` 和 `pages/my-resources/index.vue` 负责识别额度不足错误码、弹出购买引导，并在回退页面后刷新各自数据。

### 路由约定

统一使用：`/pages/vip/index?tab=addons&quotaType=publish_quota` 或 `/pages/vip/index?tab=addons&quotaType=refresh_quota`。

购买按钮始终使用已存在的 `createQuotaPackOrder` 和微信支付接口。服务端仍以订单中快照的商品、价格和权益为准，客户端不得自行传入金额或权益数量。

### 文案与价格可信度

- 只有 `salePriceCent > 0` 且低于标准价时才显示划线原价。
- 只有服务端给出非空 `saleLabel` 时才展示促销标签。
- 支付请求成功只表示微信端支付流程完成，不等同于权益已发放；提示不得承诺“已到账”。

## 异常处理

1. 购买页的商品接口失败时，不展示伪造的促销标签；已有本地兜底商品仅作为可继续下单的兼容数据，价格以后端订单为准。
2. 用户取消额度不足弹窗时，不跳转、不创建订单。
3. 用户取消微信支付时，保持页面可继续操作，显示“支付未完成”。
4. 支付完成后，页面重新拉取可见数据；权益到账由支付回调保证，未立即反映时提示用户稍后下拉刷新。

## 验收标准

1. 未开启成长活动时，登录用户点击“我的权益”仍可打开购买页，不再出现“暂无可领取权益”。
2. 余额为 0 或 1–2 时，权益卡展示对应强度的补充入口；余额充足时不展示强按钮。
3. 从发布不足、刷新不足引导进入购买页后，页面打开“购买次数”标签并突出正确商品。
4. 服务端没有返回促销标签时，VIP 页面不显示“限时特价”。
5. 支付成功后返回当前页会刷新可见数据，且不会声称权益在回调前已经到账。
6. 现有 VIP 下单、次数包下单、发布、刷新和成长任务路径保持不变。

## 测试策略

1. 更新“我的”页测试，覆盖购买页跳转、额度为零与低余额入口、无成长活动仍可进入权益页。
2. 更新 VIP 页测试，覆盖路由参数、正确商品突出与服务端促销标签。
3. 更新我的发布与发布编辑测试，覆盖额度不足弹窗和带参数跳转。
4. 执行小程序页面测试、流程校验和相关 Go 测试，确认接口错误码与现有扣减规则未被改动。
