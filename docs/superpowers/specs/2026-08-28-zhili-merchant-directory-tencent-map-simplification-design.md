# 织里拿货档口腾讯地图收缩设计

日期：2026-08-28

状态：已确认，待实施

## 1. 背景

衣货通当前只运营织里区域。“拿货档口”公开入口已经采用商家列表，商家位置页使用微信原生地图组件和腾讯地图位置能力，自定义场景画布未注册为公开页面，也不会作为正式能力上线。

但是当前商家目录、附近商家和位置纠错仍依赖 `map_scene`、`map_object`、预录档口、商家认领和后台绑定审核。自定义画布虽然没有直接展示，旧地图数据模型仍然是主链路前置条件，造成以下问题：

- 商家已经在资料页选择腾讯地图位置，仍不能自动进入拿货档口目录；
- 平台需要预录档口、维护场景、审核绑定，增加两人团队的人工成本；
- 地图领域存在 28 条 API 路由和多个超大文件，维护成本与当前业务价值不匹配；
- 商家、档口和位置数据分散在 `merchants`、`map_scene`、`map_object`，事实来源不唯一；
- “待认领”点位可能让用户把平台预录数据误认为真实入驻商家。

项目尚未正式上线，本次改造不保留旧数据库、旧 API、旧页面和旧事件名称的兼容路径，直接形成干净的最终结构。

## 2. 目标

本次改造需要达到以下目标：

1. 以 `merchants` 作为商家及唯一主档口位置的事实来源。
2. 商家自主选择腾讯地图位置后，无需平台审核即可进入拿货档口目录。
3. 拿货档口保持列表优先，只在查看位置、附近商家和导航时展示腾讯地图。
4. 未设置地图位置的商家仍可发布供需信息和展示商家主页，但不进入拿货档口目录。
5. 删除自定义地图场景、画布、预录点位、认领、绑定申请和绑定审核能力。
6. 将运营工作收缩为异常位置处理，不再人工建设或维护地图内容。
7. 保留商家目录、附近商家、腾讯地图逆地理编码、导航、位置纠错和行为统计。

## 3. 非目标

本次不实现以下能力：

- 不实现全局地图视图或列表/地图切换；
- 不支持一个商家维护多个门店或多个档口；
- 不引入 PostGIS、Redis、Elasticsearch、消息队列或腾讯距离矩阵；
- 不预录未入驻档口，不提供“待认领”数据；
- 不保留旧 `map_*` API、旧页面或旧数据库数据兼容；
- 不调整供需发布、VIP、支付和联系方式解锁规则；
- 不把地图位置设置为商家发布供需信息的前置条件。

## 4. 核心业务规则

### 4.1 一商家一个主档口位置

当前普通用户采用“一用户一商家”模型，本次同时采用“一商家一个主档口位置”。位置资料直接存储在 `merchants`，不增加 `merchant_locations` 子表。

### 4.2 位置可选

商家可以不设置位置。未设置有效位置时：

- 可以保存商家资料；
- 可以发布和管理供需信息；
- 可以展示商家主页；
- 不进入拿货档口目录；
- 不提供位置页、附近商家和腾讯地图导航入口。

### 4.3 自助公开

商家在资料页通过 `uni.chooseLocation` 选择有效位置并成功保存后，位置自动变为 `visible`，不增加额外公开开关，也不进入人工审核。

商家手工修改文字地址时，前端必须清除旧坐标；保存请求通过明确动作告诉后端设置或清除位置，禁止文字地址已经变化但继续保留旧坐标。

### 4.4 位置状态

位置状态只允许：

- `visible`：坐标有效，可进入目录、位置页、附近商家和导航；
- `hidden`：未设置位置、商家清除位置或后台人工隐藏；
- `risk_hidden`：达到位置错误报告阈值后自动隐藏。

商家重新选择有效位置后，状态恢复为 `visible`，该商家历史待处理位置报告统一结案，但保留审计记录。

### 4.5 位置错误报告

只有已登录用户可以报告商家位置错误。同一用户对同一商家最多存在一条 `pending` 报告。

当 3 名不同用户对同一商家存在待处理位置错误报告时，系统在同一事务中将商家位置状态改为 `risk_hidden`。公开目录和位置接口必须立即停止返回该位置。

后台可以将报告标记为有效或无效，并可以人工隐藏或恢复商家位置。后台状态变更和报告处理必须写入 `operation_logs`。

## 5. 数据模型

### 5.1 merchants

删除旧 `location jsonb` 字段，增加以下一等字段：

| 字段 | 类型 | 规则 |
|---|---|---|
| `market_name` | `varchar(128)` | 市场名称，可空 |
| `building_name` | `varchar(64)` | 楼栋或区域，可空 |
| `floor_no` | `varchar(32)` | 楼层，可空 |
| `booth_no` | `varchar(64)` | 档口号，可空 |
| `latitude` | `double precision` | 纬度，可空，范围 `[-90, 90]` |
| `longitude` | `double precision` | 经度，可空，范围 `[-180, 180]` |
| `location_name` | `varchar(128)` | 腾讯地图选择点名称，可空 |
| `location_status` | `varchar(32)` | `visible`、`hidden`、`risk_hidden`，默认 `hidden` |
| `location_updated_at` | `timestamptz` | 最近一次有效位置设置时间，可空 |

数据库约束：

- 纬度和经度必须同时为空或同时有值；
- `visible` 必须同时具有有效经纬度；
- `risk_hidden` 必须保留被隐藏时的经纬度，便于商家核对和后台审计；
- 商家主动清除位置时清空经纬度、位置名称及结构化档口字段，并设置为 `hidden`。

索引：

- 城市站、商家状态、资料状态和位置状态组合索引；
- 纬度、经度组合索引，用于附近商家外接矩形粗筛；
- `main_categories` GIN 索引；
- 市场名、档口号使用 `pg_trgm` 索引支持织里档口搜索。

### 5.2 merchant_location_reports

新增商家位置错误报告表：

| 字段 | 用途 |
|---|---|
| `id` | TSID 主键 |
| `merchant_id` | 被报告商家 |
| `reporter_user_id` | 报告用户 |
| `reason_code` | 固定为受控原因代码 |
| `description` | 最多 200 字补充说明 |
| `status` | `pending`、`valid`、`invalid`、`resolved` |
| `location_snapshot` | 报告时的市场、档口、地址、经纬度快照 |
| `reviewed_by` | 后台处理人，可空 |
| `review_note` | 后台处理说明，可空 |
| `reviewed_at` | 处理时间，可空 |
| `created_at` / `updated_at` | 审计时间 |

建立部分唯一索引，保证同一用户对同一商家最多一条 `pending` 报告。

### 5.3 merchant_directory_events

使用商家目录行为表替代 `merchant_map_events`，支持以下稳定事件：

- `directory_exposure`
- `directory_merchant_click`
- `location_view`
- `nearby_marker_click`
- `nearby_list_item_click`
- `nearby_merchant_click`
- `nearby_drawer_open`
- `navigation_click`
- `location_report_submit`

保留匿名 `visitor_key`、登录用户、会话、来源、当前商家、目标商家、事件时间和保留期清理能力。事件不能记录联系人、手机号、详细地址、Token 或原始请求体。

### 5.4 删除的数据结构

冷启动迁移不再创建：

- `map_scene`
- `map_object`
- `map_category`
- `map_object_bind_request`
- `map_object_reports`
- `merchant_map_events`

直接移除与上述表对应的旧迁移文件，修改 `000002_core_domain` 和 `000003_seed_zhili` 形成最终结构。迁移编号允许保留空号，不新增“创建后再删除”的兼容迁移。

## 6. API 设计

### 6.1 商家资料

`MerchantDetailResp` 删除无类型约束的 `location map[string]interface{}`，增加结构化位置响应。

`UpdateMerchantReq` 增加：

- `locationAction`：`set` 或 `clear`；
- `marketName`
- `buildingName`
- `floorNo`
- `boothNo`
- `latitude`
- `longitude`
- `locationName`

商家资料页每次保存完整状态：存在有效坐标时发送 `set`，否则发送 `clear`。后端不接收 `keep`，避免部分更新导致文字地址和坐标语义漂移。

### 6.2 拿货档口目录

新增公开接口：

```text
GET /api/v1/merchant-directory
```

查询参数：

- `cityCode`：当前固定使用 `zhili`，后端仍校验站点；
- `keyword`：匹配商家名、市场名、楼栋和档口号；
- `categories`：匹配 `merchants.main_categories`；
- `page` / `pageSize`：默认 1/20，单页上限 100。

只返回 active、资料 completed、位置 visible、经纬度有效的真实入驻商家。

排序规则：

1. 有关键词时，档口号精确匹配、商家名精确匹配、前缀匹配、部分匹配依次优先；
2. 其次按最近一条已发布供需信息的刷新或发布时间倒序；
3. 再按商家最近活跃时间和 ID 倒序，保证稳定分页。

公开响应包含商家 ID、编号、名称、类型、主营品类、Logo、市场、楼栋、楼层、档口号、公开地址、经纬度和最近资源活跃时间，不包含完整联系方式。

### 6.3 商家位置上下文

```text
GET /api/v1/merchants/:merchantId/location-context
```

当前商家必须满足目录公开条件。附近商家以当前商家为原点：

- 半径固定 1000 米；
- 最多返回 20 家；
- 数据库先按经纬度外接矩形粗筛；
- Go 使用 Haversine 公式精确计算距离并排序；
- 附近查询失败时保留当前商家及导航能力，并返回 `nearbyAvailable=false`。

### 6.4 位置错误报告

```text
POST /api/v1/merchants/:merchantId/location-reports
```

要求用户登录。后端从 Token 获取报告用户，不信任请求体用户 ID。接口校验商家当前位置可见、原因代码合法和说明长度，并在事务中完成报告写入、阈值统计及自动隐藏。

### 6.5 管理后台

在商家管理领域增加：

- 按位置状态筛选商家；
- 查看待处理位置错误报告；
- 将报告标记为有效、无效或已解决；
- 人工隐藏或恢复商家位置。

不保留独立地图后台模块。

### 6.6 删除的 API

删除 `map.api` 中全部场景、对象、分类、附近 POI、预录点位、绑定候选、绑定状态、绑定申请和绑定审核接口。商家目录、位置上下文和报告接口迁入 `merchant.api`；行为上报迁入 `metrics.api`。

`.api` 是外部契约唯一来源，修改后必须通过项目固定的 goctl 1.7.5 和仓库模板生成 routes/types，禁止手工修改生成文件。

## 7. 小程序设计

### 7.1 拿货档口

`pages/sourcing-map/index.vue` 保留现有 Tab 路径和“拿货档口”文案，但语义改为商家目录：

- 保留关键词搜索、主营品类筛选、分页、刷新和空态；
- 删除“全部商家/已入驻/待认领”筛选；
- 删除预录点位、认领提示和“这是我的档口”；
- 卡片主操作为进入商家主页和查看位置；
- 不展示全局地图，不请求用户当前位置；
- 目录接口失败时保留明确重试入口和安全中文提示。

### 7.2 商家位置页

保留微信原生 `<map>`、当前商家、1000 米内附近商家、Marker 联动、商家详情和 `uni.openLocation` 导航。

位置报告对象从 `objectId` 改为 `merchantId`。用户从腾讯地图导航返回后仍可以报告位置不准确，但不再依赖本地保存的地图对象 ID。

### 7.3 商家资料页

在经营地址区域增加市场、楼栋、楼层和档口号输入。腾讯地图选择负责经纬度和位置名称，结构化档口字段由商家核对填写。

手工修改地址、点击清除位置或腾讯地图重新选择失败时，不允许静默保留旧坐标。提交期间继续使用现有请求互斥和友好反馈模式。

### 7.4 删除页面和代码

删除：

- `pages/merchant/map-binding.vue`
- `pages/sourcing-map/legacy-canvas.vue`
- 自定义画布渲染、手势、命中测试和对象状态模块；
- 仅服务预录档口、场景和绑定的组件、API 方法、静态资源及测试。

`pages.json`、页面校验脚本和流程测试同步删除旧页面引用。

## 8. 管理后台设计

删除独立拿货地图菜单、路由和 `SourcingMapView.vue`。

在商家管理页增加位置状态筛选、位置摘要和异常操作：

- 市场、楼栋、楼层、档口号；
- 位置状态和最近更新时间；
- 待处理报告数量；
- 查看报告；
- 隐藏位置；
- 恢复位置。

后台不编辑商家坐标，不承担地图数据录入。需要纠正时由商家在小程序重新选择腾讯地图位置，后台只处理风险和争议。

## 9. 日志与错误处理

遵循“日志给工程师、错误给用户、注释给维护者”的规则。

必须记录：

- 商家设置、清除、自动隐藏和后台恢复位置时的 `merchantId`、旧状态、新状态和操作来源；
- 目录、附近商家和报告数据库失败时的操作名、商家 ID、分页或半径等安全上下文及根错误；
- 第 3 名不同用户触发自动隐藏时的商家 ID 和有效报告数量；
- 腾讯逆地理编码继续使用 `external_call` 白名单日志，不记录 Key、完整 URL、详细地址或响应体。

前端安全错误示例：

- “商家列表加载失败，请稍后重试”
- “该商家位置待完善”
- “附近商家加载失败，请重试”
- “位置反馈提交失败，请稍后重试”
- “地图位置格式不正确，请重新选择”

不得返回 SQL、表名、原始第三方错误、Token、手机号或内部堆栈。

- 商家位置成对经纬度和状态约束；
- 商家设置、清除和风险隐藏事务；

### 10.2 Logic、Handler 与权限

## 12. 验收标准

1. 商家设置有效腾讯地图位置后，无需人工审核即可进入拿货档口目录。
2. 未设置位置的商家可以正常发布供需，但不会进入档口目录或附近商家。
3. 用户可以按商家名、市场、楼栋、档口号和主营品类查询。
4. 位置页展示当前商家和 1000 米内最多 20 家附近商家，并可以腾讯地图导航。
5. 三名不同登录用户报告位置错误后，该商家位置自动变为 `risk_hidden` 并停止公开。
6. 商家重新选择位置后恢复公开，旧待处理报告结案。
7. 管理后台只处理位置异常，不再包含场景编辑、点位标注和绑定审核。
8. 公开及后台运行时路由不再包含旧地图场景、对象、预录和绑定接口。
9. 干净数据库不创建任何旧自定义地图表。
10. 仓库不再包含自定义画布、地图绑定页面及仅服务这些能力的生产代码。
11. 自动化测试、静态检查、后台构建和小程序构建全部通过。
