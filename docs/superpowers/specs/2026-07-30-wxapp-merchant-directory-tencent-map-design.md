# wxapp 商家列表与腾讯地图重构设计

日期：2026-07-30
适用范围：衣货通微信小程序、商家地图公开查询接口、首页运营位后台配置

## 1. 背景

衣货通首期定位已经收敛为“织里童装产业拿货地图 + 供需信息撮合平台”。采购用户进入拿货地图后的首要任务不是浏览抽象地图对象，而是快速找到真实档口或工厂、判断主营方向，并完成地图定位或到店导航。

当前小程序使用自定义 Canvas 绘制场内底图、档口和 POI。该方案适合未来的市场内部导览，但首期需要继续维护底图、场景坐标、手势、命中检测、视口绘制和后台标注，成本较高，也无法直接提供用户熟悉的道路、街区和第三方导航体验。

本设计将首期拿货地图调整为“商家列表优先、腾讯地图按需查看”：

- 默认展示商家与预收录档口列表。
- 地图视图使用微信小程序原生 `map` 组件展示腾讯地图底图。
- 商家位置统一使用真实经纬度，不再依赖自定义场内坐标。
- 现有自定义 Canvas 地图代码和数据暂时保留，但退出首发用户主路径。

## 2. 已确认的核心决策

1. 拿货地图的第一目标是“找商家并到店导航”。
2. 页面默认展示商家列表，不默认展示地图。
3. 用户可以切换到腾讯地图查看当前搜索结果的位置。
4. 搜索结果包含已认领商家和平台预收录但尚未认领的档口。
5. 已认领商家与预收录档口必须明确区分，不能把预收录资料包装成已入驻或已认证商家。
6. 搜索结果不混入供需信息；供需信息继续由独立供需市场和商家主页承接。
7. 首页 Banner 位置保持不变，可以由后台配置跳转拿货地图并携带初始条件。
8. 拿货地图仍保留稳定入口，不能只依赖临时 Banner。
9. 商家主页不公开电话和微信，联系方式只跟随有效供需信息展示。
10. VIP 套餐、VIP 入口和相关首期引导暂时隐藏。
11. 现有自定义 Canvas 地图首期不使用，但不删除代码、表结构和历史标注数据。

## 3. 产品边界

### 3.1 首期覆盖

- 商家列表与关键词搜索。
- 主营品类、商家类型、市场街区、认领状态等筛选。
- 已认领商家和平台预收录档口展示。
- 商家列表与腾讯地图双视图。
- 腾讯地图 Marker、选中态和商家摘要卡。
- 地图拖动后的“搜索此区域”。
- 商家主页、档口资料、地图定位和第三方导航。
- 预收录档口认领入口。
- 导航后的找店反馈、位置纠错和风险举报入口。
- 首页 Banner 和固定入口向拿货地图引流。
- 商家搜索、地图定位、导航和认领漏斗统计。

### 3.2 首期不覆盖

- 自定义市场底图和 Canvas 场内地图。
- 商场或市场楼层内部导航。
- 自动路径规划。
- 地址自动解析经纬度。
- 地图点位聚合算法。
- 复杂商家评分和信用分。
- 商家主页公开联系方式。
- VIP 套餐售卖和 VIP 排序权益。
- 在拿货地图搜索结果中混排供需信息。

## 4. 信息架构

### 4.1 一级导航

小程序一级导航调整为：

`首页｜拿货地图｜发布｜供需｜我的`

- “拿货地图”作为首期核心能力进入一级导航。
- “消息”移入“我的”，通过未读角标或顶部入口提醒。
- “发布”继续保留高优先级入口。
- “供需”继续承接具体货源、库存、工厂产能和需求信息。

### 4.2 首页

首页结构保持：

1. 品牌栏。
2. 搜索入口。
3. Banner。
4. 快捷入口。
5. 近期供需。

Banner 位置不调整。后台可将 Banner 配置为内部页面跳转：

```text
/pages/sourcing-map/index?view=list
```

可选带条件跳转：

```text
/pages/sourcing-map/index?view=list&category=kids_wholesale
/pages/sourcing-map/index?view=map&marketCode=liji-road
/pages/sourcing-map/index?view=list&claimed=true
```

Banner 用于运营强化和专题引流，不能替代一级导航和首页固定快捷入口。

## 5. 拿货地图页面

### 5.1 页面模式

页面顶部提供两种视图：

`商家列表｜地图`

默认规则：

- 首次进入默认商家列表。
- 记录用户上一次主动选择的视图。
- Banner 或业务入口显式携带 `view` 时，以路由参数为准。
- 两种视图共享关键词、筛选、排序和选中商家。

### 5.2 商家列表布局

页面结构：

1. 标题与视图切换。
2. 搜索框。
3. 快捷主营分类。
4. 更多筛选。
5. 结果数量与排序。
6. 商家或档口列表。

搜索框文案：

> 搜商家名、档口号、主营品类

快捷筛选第一版包含：

- 童装批发。
- 工厂。
- 库存。
- 面料辅料。
- 配套服务。

更多筛选包含：

- 市场或街区。
- 楼栋、楼层。
- 主营品类。
- 商家类型。
- 只看已认领。

只有用户明确授权位置后才展示“距离最近”排序。地图浏览、商家搜索和按地址导航不强制申请用户当前位置。

### 5.3 商家卡

商家卡使用“档口门牌”作为识别元素，避免使用通用品牌封面充当缺图占位。

已认领商家展示：

- 商家名称。
- 档口号。
- 市场、街区、楼栋和楼层。
- 主营品类与服务标签。
- 门头或现场图片；缺图时展示档口门牌。
- “商家自主认领”。
- 最近确认时间。
- “进入主页”和“地图定位”。

平台预收录档口展示：

- 档口或已知商家名称。
- 档口号和地址。
- 已知主营线索。
- “平台预收录 · 待认领”。
- 资料更新时间。
- “查看资料”“地图定位”和“这是我的档口”。

预收录档口不展示联系方式、认证、评分、虚构热度或交易数据。

### 5.4 腾讯地图视图

腾讯地图视图使用微信小程序原生 `map` 组件。地图只负责：

- 展示道路、街区和真实地理位置。
- 展示当前搜索结果对应的商家 Marker。
- 选择商家。
- 打开商家摘要。
- 发起第三方导航。

不在原生地图气泡中承载复杂商家内容。点击 Marker 后，通过小程序自己的底部商家摘要卡展示详情。

Marker 状态：

- 已认领商家：深蓝实心 Marker。
- 平台预收录档口：白底蓝边 Marker。
- 当前选中商家：橙色放大 Marker。
- 位置存在风险：附加警告状态。
- 配套服务：只在用户选择配套分类后展示。

列表中的商家没有可靠经纬度时仍可展示，但不能生成 Marker，也不能提供第三方导航。

### 5.5 地图交互

从列表切换到地图时：

1. 沿用当前搜索条件。
2. 使用当前结果经纬度适配地图可视范围。
3. 如果携带 `objectId`，直接居中并选中对应商家。

用户拖动或缩放地图后：

1. 不自动请求新结果。
2. 显示“搜索此区域”。
3. 用户点击后，使用当前地图边界重新查询。
4. 新结果更新 Marker 和商家列表。

从地图切回列表时：

- 保留当前区域和筛选条件。
- 列表滚动到当前选中的商家。

### 5.6 路由参数

拿货地图支持：

```text
/pages/sourcing-map/index?view=list
/pages/sourcing-map/index?view=map
/pages/sourcing-map/index?marketCode=liji-road
/pages/sourcing-map/index?category=kids_wholesale
/pages/sourcing-map/index?claimed=true
/pages/sourcing-map/index?objectId=123
```

参数均为可选。无效参数不阻断页面，按默认列表和默认城市站降级。

## 6. 搜索与排序

### 6.1 搜索字段

商家搜索覆盖：

- 商家名称。
- 档口号。
- 市场、街区、道路、楼栋和楼层。
- 主营品类。
- 商家类型。
- 服务标签。
- 平台预收录搜索关键词。

### 6.2 排序

默认综合排序依次考虑：

1. 商家名称或档口号精确匹配。
2. 主营品类和服务标签匹配。
3. 当前市场或街区匹配。
4. 已认领且近期确认。
5. 用户授权位置后的距离。
6. 平台预收录但尚未认领的档口。

不因 VIP 获得隐性排序。未来付费推广如进入列表，必须明确标记“推广”，并保持基础相关性约束。

### 6.3 搜索结果边界

商家列表只展示可作为商家访问目标的对象：

- 已认领商家。
- 平台预收录档口。
- 用户主动筛选配套服务后匹配的配套商家或 POI。

道路、区域边界、普通空档口和无业务意义的地图对象不进入商家列表。

搜索到“库存清仓”“找加工厂”等供需意图时，不混排供需卡片，只提示：

> 当前正在搜索商家。需要查找具体供需信息，可前往供需市场。

## 7. 详情、认领与导航

### 7.1 已认领商家主页

商家主页优先展示：

- 商家名称和档口号。
- 商家类型和主营品类。
- 市场、街区、楼栋、楼层和地址。
- “商家自主认领”和最近确认时间。
- 门头、展厅或工厂实拍。
- 地图定位和导航。
- 当前有效供需信息。
- 关注、位置纠错和风险举报。

不展示：

- 联系人姓名。
- 电话和微信。
- VIP 标识。
- 认证背书。
- 含义不明确的综合热度。

### 7.2 平台预收录档口资料

预收录档口使用轻量资料页，不复用完整商家主页：

- 档口名称或已知商家名称。
- 档口号与地址。
- 已知主营线索。
- “平台预收录 · 尚未认领”。
- 资料更新时间。
- 地图定位、可用时的导航。
- “这是我的档口”。

### 7.3 档口认领

认领流程：

1. 用户点击“这是我的档口”。
2. 未登录时完成微信登录。
3. 没有商家主体时填写最低商家资料。
4. 展示档口名称、编号和位置，要求二次确认。
5. 系统检查商家是否已有主档口、点位是否已被认领、名称是否明显重复。
6. 低风险认领直接绑定成功。
7. 冲突或高风险情况进入异常处理。

正常认领不使用“等待人工审核”文案。成功提示：

> 主档口已绑定，其他用户现在可以在拿货地图中找到你。

### 7.4 导航

有可靠经纬度时使用 `uni.openLocation`：

```js
uni.openLocation({
  latitude,
  longitude,
  name,
  address,
})
```

没有可靠经纬度时：

- 不显示第三方导航。
- 提供文字地址复制。
- 提示“地图位置待补充”。

首期不根据文字地址自动生成经纬度。经纬度必须来自商家地图选点或后台人工选点。

### 7.5 导航反馈

用户从第三方地图返回后，可进行一次轻量反馈：

- 找到了。
- 位置不准确。
- 商家已不在这里。

“位置不准确”进入位置纠错；“商家已不在这里”进入营业状态反馈。风险举报保持独立。

达到后台配置的位置异常阈值后：

- 商家卡显示“位置近期可能有误”。
- 导航前增加提示。
- 必要时暂停第三方导航，但保留商家资料和地图点位。

## 8. 数据接口

### 8.1 商家位置列表接口

新增公开接口：

```text
GET /api/v1/map/merchant-places
```

查询参数：

- `cityCode`
- `marketCode`
- `keyword`
- `categoryCodes`
- `merchantTypes`
- `claimed`
- `page`
- `pageSize`
- `sort`
- `minLat`
- `maxLat`
- `minLng`
- `maxLng`
- 用户授权后的 `lat`
- 用户授权后的 `lng`

列表模式使用分页参数；“搜索此区域”使用地图边界参数。服务端统一执行搜索和排序，避免前端列表与地图规则不一致。

### 8.2 返回字段

每条商家位置至少返回：

- `objectId`
- 可选 `merchantId`
- `name`
- `code`
- `merchantType`
- `categoryCodes`
- `categoryNames`
- `serviceTags`
- `marketCode`
- `marketName`
- `building`
- `floor`
- `address`
- `coverUrl`
- `claimed`
- `sourceType`
- `lastConfirmedAt`
- `updatedAt`
- 可选 `latitude`
- 可选 `longitude`
- `locationRiskStatus`
- 可选 `distanceMeters`

`sourceType` 首期至少区分：

- `merchant_claimed`
- `platform_prelisted`

### 8.3 地图数据边界

首期公开商家位置接口不依赖自定义底图、场景宽高、Canvas geometry 或内部地图缩放层级。现有自定义地图 API 保留兼容，但新页面主路径不调用。

## 9. 前端组件边界

地图页不继续在现有超大页面中叠加功能，拆分为：

- `MerchantExplorer`：管理搜索、筛选、排序、选中项和视图切换。
- `MerchantSearchBar`：关键词输入和搜索提交。
- `MerchantFilterSheet`：完整筛选。
- `MerchantPlaceList`：分页、加载和空状态。
- `MerchantPlaceCard`：已认领和预收录卡片。
- `TencentMerchantMap`：原生 `map`、Marker、视野和区域事件。
- `MapMerchantSheet`：地图选中商家摘要。
- `MerchantClaimEntry`：档口认领入口。

列表和地图共享一个查询状态对象。腾讯地图组件只接收商家位置结果和当前选中项，不负责业务搜索、排序或认领。

## 10. 首页后台配置

现有 Banner 数据协议继续使用 `jumpType=internal` 和 `jumpTarget`，不新增跳转类型。

后台调整：

- 内部页面选项增加“拿货地图”。
- 删除已经下线的“认证页”选项。
- 允许选择默认列表或地图视图。
- 可选配置主营分类、市场和只看已认领。
- 保存时生成稳定内部路径，不要求运营手写查询字符串。

Banner 点击继续进入曝光和点击统计，并携带 Banner ID 作为拿货地图来源。

## 11. VIP 首期隐藏

首期处理：

- “我的”移除 VIP 权益入口。
- 首页和 Banner 不配置 VIP 引流。
- 发布额度不足不引导开通 VIP。
- 商家列表、地图、商家主页和供需信息不展示 VIP。
- VIP 不影响搜索或地图排序。
- VIP 页面、后端接口、支付能力和历史数据暂不删除。

首期商业化只在具体动作中展示：

- 购买额外发布次数。
- 立即刷新。
- 资源置顶。
- 后续明确标记的急需专区推广。

## 12. 视觉方向

沿用现有品牌基础：

- 深墨蓝 `#061625`：主文字、已认领 Marker、主按钮。
- 行动橙 `#C23A00`：选中 Marker、关键行动。
- 地图蓝 `#1677FF`：地图定位与辅助链接。
- 页面浅蓝灰 `#F4F7FD`：页面背景。
- 卡片白 `#FFFFFF`：卡片和底部摘要。
- 状态绿 `#16A36A`：成功和有效状态。

核心视觉签名是“档口门牌”：

- 商家卡缺图时展示门牌。
- 地图摘要展示档口号。
- 商家主页首屏展示档口编号。
- 门牌编码使用清晰、紧凑的数字与字母组合。

除门牌外保持克制，不增加无业务含义的渐变、装饰编号或营销徽章。

## 13. 异常与空状态

### 13.1 商家列表失败

- 保留关键词和筛选。
- 显示“重新加载”。
- 不自动清除用户条件。

### 13.2 腾讯地图失败

- 商家列表继续可用。
- 提示“地图暂时无法加载，可继续查看商家列表”。
- 不阻断商家主页和地址复制。

### 13.3 无搜索结果

提供：

- 清除筛选。
- 更换关键词。
- 切换地图查看附近档口。
- 前往供需市场。

### 13.4 无经纬度

- 列表继续展示。
- 显示“地图位置待补充”。
- 不生成 Marker。
- 不提供第三方导航。

### 13.5 认领冲突

明确区分：

- 当前商家已经绑定主档口。
- 目标档口已被其他商家认领。
- 资料不完整。
- 系统检测到疑似重复或异常，需要进一步处理。

## 14. 数据统计

采购用户漏斗：

```text
Banner或固定入口
→ 商家列表曝光
→ 搜索或筛选
→ 商家卡点击
→ 地图定位
→ 导航
→ 导航反馈
```

商家侧漏斗：

```text
预收录档口曝光
→ 点击认领
→ 完善商家资料
→ 绑定主档口
→ 发布有效供需
→ 查看曝光、导航和联系效果
```

首期至少统计：

- 来源入口。
- 搜索词和筛选。
- 商家卡曝光和点击。
- 列表/地图切换。
- Marker 点击。
- 地图定位。
- 导航点击。
- 导航反馈。
- 认领入口点击和认领结果。

## 15. 验收标准

### 15.1 用户体验

- 首页 Banner 位置不变，并可由后台配置跳转拿货地图。
- 拿货地图可通过一级导航和首页固定入口稳定访问。
- 页面默认展示商家列表。
- 商家列表和腾讯地图可以切换。
- 两种视图共享关键词、筛选和选中商家。
- 已认领商家和平台预收录档口区分明确。
- 搜索结果不混入供需信息。
- 商家可以从列表定位到腾讯地图。
- 地图可以通过 Marker 打开商家摘要。
- 用户拖动地图后可以主动“搜索此区域”。
- 无经纬度的档口不会错误导航。
- 预收录档口可以进入认领流程。
- 商家主页不公开联系方式。
- VIP 套餐和入口不可见。

### 15.2 技术验证

- 新商家位置接口具备分页、筛选、排序和地图边界查询。
- 原生 `map` 组件能够展示 Marker、选中态和当前结果范围。
- 自定义 Canvas 地图不再出现在首发用户路径。
- 自定义地图代码、数据表和后台历史数据未被删除。
- 地图失败时商家列表仍可使用。
- 当前小程序页面验证和流程验证通过。
- 小程序自动化测试通过。
- `build:mp-weixin` 通过。
- 微信开发者工具和至少一台真机完成列表、地图、导航和返回反馈验收。

## 16. 实施优先级

1. 调整一级导航、隐藏 VIP、增加 Banner 拿货地图目标。
2. 新增商家位置查询接口和服务端排序。
3. 实现商家列表和档口门牌卡片。
4. 接入原生腾讯地图、Marker 和“搜索此区域”。
5. 打通列表定位、地图摘要和商家主页。
6. 打通预收录档口认领。
7. 补充导航反馈、位置纠错和统计。
8. 完成微信开发者工具与真机验收。
