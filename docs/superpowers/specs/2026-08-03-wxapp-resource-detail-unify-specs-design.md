# 供需详情参数合并设计

## 目标

去除详情页中由系统拼接的自动标题，避免与价格、数量和类型信息重复。将价格/预算、数量/面积与发布类型属性合并为一个“详细参数”区块，让信息层级更直接；发布者填写的描述继续作为“补充说明”展示。

## 范围

### 包含

1. 自动摘要卡仅保留供应/需求标识、二级类型和发布标签。
2. 不再渲染 `detailPresentation.headline` 和 `detailPresentation.facts`。
3. 详细参数按“数量/面积、价格/预算、类型属性”的顺序合并展示。
4. 价格或数量为空时不生成对应参数项；原有长文本整行展示规则继续适用。
5. 用户真实填写的 `description` 继续以“补充说明”独立展示，描述为空时不展示该区块。
6. 更新展示状态工具和详情页回归测试。

### 不包含

1. 不改变发布端自动生成 `title` 的逻辑或已存数据。
2. 不调整图片、地址、商家资料、推荐、联系、收藏和管理功能。
3. 不增加接口、配置、数据库字段或迁移。

## 页面结构

```text
图片（有图时）
供/需标识 · 二级类型 · 发布标签
补充说明（仅描述非空）
详细参数：数量/面积、价格/预算、类型属性
地址 → 商家资料 → 同类推荐 → 交易提示
```

## 前端设计

- `buildResourceDetailPresentation` 保留供需方向、名词和类型名称，不再为页面提供组合标题或核心事实卡片。
- 详情页在 `attributeSpecItems` 前构造两个核心参数候选项：数量/面积使用 `quantityText`；需求使用“预算/报价”、供应使用“价格/报价”，值均来自 `priceText`。
- 核心参数仅在有值时加入，再和非地址的类型属性一起传入 `buildDetailSpecItems`。该函数继续负责长文本或语义字段的整行展示。
- 地址仍使用独立地址区块，因此不会在合并后的参数区重复出现。

## 验收标准

1. 详情页不再渲染自动组合标题或单独的核心事实卡片。
2. 描述存在时只以“补充说明”展示，未填写时不占位。
3. 数量/面积和价格/预算位于详细参数最前，值为空时隐藏。
4. 需求详情使用“预算/报价”，供应详情使用“价格/报价”。
5. 原有类型参数、长文本整行、地址独立和有图/无图布局行为保持不变。
