# 小程序首页商家与供需共用列表项重构设计

日期：2026-08-01

## 1. 背景

首页已经将“新入驻商家”和“近期供需”合并为双标签内容区，也通过 `MerchantListItem` 让首页商家卡片与拿货地图商家卡片复用了部分基础结构。但当前实现仍有两个问题：

1. 首页“近期供需”使用 `ResourceCard` 的 `home` 样式，与供需市场最新使用的紧凑列表样式不一致。
2. 供需市场的紧凑样式分别写在 `ResourceCard` 和 `DemandCard` 的 `market` 分支中，两份模板、数据整理逻辑和样式高度重复。

本次重构只统一列表视觉并收敛重复组件，不改变首页双标签、后端接口、内容排序、展示数量、降级策略或页面跳转。

## 2. 目标

1. “新入驻商家”沿用拿货地图商家列表的基础卡片视觉。
2. “近期供需”与供需市场使用同一个紧凑供需列表项。
3. 统一处理供应与需求数据，根据 `direction` 展示正确的类型文案和色彩。
4. 删除 `ResourceCard` 与 `DemandCard` 中重复的 `market` 模板和样式。
5. 保持现有首页、拿货地图和供需市场的业务行为不变。

## 3. 组件设计

### 3.1 商家列表项

保留现有三层结构：

- `MerchantListItem`：负责通用容器、标题、辅助信息、标签、底部元信息、操作区和选中态。
- `HomeRecentMerchantCard`：提供 Logo 或名称首字、新入驻标识、商家类型、主营品类和入驻时间。
- `MerchantPlaceCard`：提供档口门牌、市场位置、入驻状态、距离和地图专属操作。

首页和拿货地图继续复用 `MerchantListItem`，不把地图导航、认领、档口选择等动作带入首页，也不新增包含大量场景判断的商家万能组件。

### 3.2 共用供需列表项

新增 `ResourceFeedCard`，作为首页“近期供需”和供需市场共同使用的紧凑列表项。组件直接接收完整 `resource` 对象，在内部完成以下展示数据整理：

- 判断 `direction` 是供应还是需求；
- 解析封面图和默认图；
- 解析动态供需类型名称；
- 整理标题、数量、价格、商家名称和更新时间；
- 展示已完成状态；
- 对缺失字段使用现有安全兜底文案。

视觉结构统一为：

```text
┌──────────┬──────────────────────────┐
│ 类型标识 │ 标题                     │
│  方形图  │ 数量                价格 │
│          │ 商家名称          更新时间 │
└──────────┴──────────────────────────┘
```

供应使用现有主色，需求使用现有警示色。卡片尺寸、图片比例、字号、间距和阴影沿用供需市场当前的 `market` 样式。

### 3.3 旧组件收敛

- `ResourceCard` 保留原有默认、`home` 和 `compact` 展示能力，但移除 `market` 分支。
- `DemandCard` 保留原有详细需求卡能力，但移除 `market` 分支。
- 供需市场不再根据方向分别加载 `ResourceCard` 和 `DemandCard`，统一使用 `ResourceFeedCard`。
- 首页“近期供需”也统一使用 `ResourceFeedCard`，不再使用 `ResourceCard variant="home"`。

该边界能复用真正相同的紧凑列表结构，同时避免影响其他仍需要详细信息卡片的页面。

## 4. 页面接入

### 4.1 首页

首页保留现有双标签状态和数据加载流程：

1. 首页运营配置、新入驻商家和近期供需继续并行加载。
2. 有新商家时默认选中“新入驻商家”；否则显示“近期供需”。
3. 两类内容都有数据时显示双标签；只有一类内容时隐藏切换控件。
4. 切换标签只切换本地内容，不重新请求接口。

模板调整仅限：

- 商家标签继续渲染 `HomeRecentMerchantCard`；
- 供需标签改为渲染 `ResourceFeedCard`；
- 保留 `ResourceExposure`、推荐卡和“查看更多供需”入口。

### 4.2 供需市场

供需市场保留筛选、分页、曝光统计和详情跳转，只把列表中的方向分支替换为单一的 `ResourceFeedCard`。组件内部根据 `resource.direction` 呈现供应或需求，不改变接口返回或列表排序。

### 4.3 拿货地图

拿货地图页面不修改数据加载、筛选、地图切换、导航、认领和详情跳转。只通过现有 `MerchantListItem` 继续与首页共享基础视觉规范。

## 5. 数据与交互约束

- 不修改 `GET /api/v1/home/recent-merchants` 和首页供需接口。
- 不修改新入驻商家的资格、排序和最多 6 家限制。
- 不修改近期供需的排序、数量和公开列表兜底逻辑。
- 不修改供需市场的筛选、分页和曝光来源值。
- 点击商家仍进入商家主页；点击供需仍进入供需详情。
- “查看更多商家”仍进入拿货地图，“查看更多供需”仍进入供需搜索。
- 供需列表不新增认证、平台核实、VIP、会员或权益标识。

## 6. 异常与兜底

- 无图片时继续使用现有默认供需封面。
- 无标题时按方向显示“供应标题待完善”或“需求标题待完善”。
- 无商家名称时按方向显示“商家待确认”或“采购方待确认”。
- 数量和价格都缺失时显示“交易信息待完善”。
- 更新时间缺失时不渲染时间占位。
- 首页任一接口失败时继续沿用现有静默降级行为，不由展示组件发起请求或弹出提示。

## 7. 测试与验收

### 7.1 组件测试

1. `ResourceFeedCard` 能根据 `direction` 正确展示供应和需求状态。
2. 供应和需求使用各自现有颜色，其他布局完全一致。
3. 图片、类型、标题、数量、价格、商家、更新时间和已完成状态均正确展示。
4. 缺失图片、标题、交易信息和商家名称时使用预期兜底。
5. 点击卡片只触发一次 `open` 事件。

### 7.2 页面测试

1. 首页“近期供需”使用 `ResourceFeedCard`，并保留 `ResourceExposure source="home"`。
2. 首页“新入驻商家”继续通过 `HomeRecentMerchantCard` 复用 `MerchantListItem`。
3. 供需市场统一使用 `ResourceFeedCard`，并保留 `ResourceExposure source="list"`。
4. 首页双标签状态、默认标签、空数据降级和“查看更多”跳转保持不变。
5. 拿货地图的详情、导航、认领和选中态测试保持通过。

### 7.3 回归验证

- 运行供需卡片、首页、供需市场、商家卡片和拿货地图定向测试。
- 运行微信小程序完整测试。
- 构建 `mp-weixin`。
- 检查常见手机宽度下的卡片图片比例、长标题截断、价格对齐和标签切换布局。

## 8. 非目标

- 不重做首页整体布局或双标签交互。
- 不调整 Banner、快捷入口和推荐卡。
- 不修改任何后端接口或数据库结构。
- 不增加新的商家或供需字段。
- 不调整拿货地图和供需市场的筛选工具栏。
- 不扩展商家评分、热度、联系方式、认证或商业权益展示。
