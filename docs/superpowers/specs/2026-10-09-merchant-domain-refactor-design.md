# 商家资料与位置专项重构设计

本次落实已经确认的商家专项重构，不实施整个地图首发 PRD，也不重写资源发布。当前仓库已经使用 merchants 的结构化位置提供目录，不再增加 map_object 同步流程。

## 边界与决策

1. 保留商家 ID、管理关系、公开接口字段、现有 set/clear 位置操作和资源归属。
2. 请求归一化与校验集中在商家资料构建文件；坐标有效性集中在 model 的位置规则文件，供写入、主页和位置治理复用。
3. 商家更新事务从通用查询文件中拆出，事务继续覆盖资料、位置报告结案与身份变更记录；任一步失败全部回滚。
4. 资料完整性以有效名称和至少一项主营判断，独立于位置状态；没有位置的商家仍可完善资料和沿用资源发布能力。只有完整资料首次保存才记录 onboarded_at，后续保留首次时间。
5. 位置重新选择后的风险报告结案规则保持兼容；人工隐藏与自助重新公开的策略、联系方式公开授权、草稿接口及模块开关另属首发产品实施，不在结构重构中混入数据库变更。
6. 不新增表、不手改生成代码。状态转换放在可单测规则中，持久化只执行最终结果。

## 日志

写入日志带 merchantId、action、stage、old/new profileStatus、old/new locationStatus、耗时和结案报告数；成功只在事务提交后记录。失败使用稳定阶段名、错误类型和 SQLSTATE，不记录原始数据库错误正文，因为错误详情可能包含电话、地址或 SQL 参数。原错误通过 Unwrap 保留供服务内 errors.Is/As 判断，前端收到明确中文消息。

## 验证

测试覆盖资料与位置状态独立、未知操作、坐标边界、无效存量坐标不公开、报告和身份日志失败回滚、提交失败、敏感错误日志脱敏；运行商家、模型、handler 和资源模块回归。补充维护文档说明职责入口及排错步骤。
