# 拿货档口标签中文化设计

## 背景

“拿货档口”列表中的商家卡片直接展示接口返回的 `categoryCodes` 和 `serviceTags`。这些字段是用于筛选与存储的稳定代码，例如 `girl`、`spot`、`factory`，导致用户看到英文标签。顶部分类筛选已通过分类接口展示中文名称，卡片与筛选的语言不一致。

## 目标与范围

将档口卡片中的品类和服务标签转换为运营配置的中文名称。改动仅限小程序拿货档口列表及其测试，不调整接口字段、数据库数据、筛选参数或其他页面。

## 方案

页面加载 `booth_category` 分类时，保存代码到名称的映射；同时加载 `booth_service` 与 `platform_tag` 分类，以覆盖卡片中可能出现的服务标签和平台标签。列表数据规范化后，依据该映射生成供卡片展示的中文标签。

卡片只显示已转换的展示标签，保留最多三个的现有上限。若运营端新增代码在分类接口尚未返回，保留原始值，避免标签被静默隐藏；中文原值保持不变。

## 数据流

1. 页面请求三类可见分类配置，并合并为 `code -> name` 映射。
2. 页面请求档口列表，获得原始 `categoryCodes`、`serviceTags` 与 `platformTags`。
3. 页面将原始标签按映射转换后传入商家卡片。
4. 商家卡片渲染中文展示标签；搜索与筛选仍继续使用原始代码。

## 验收标准

1. `girl`、`middle_child`、`spot`、`factory`、`sample` 等示例代码在档口卡片分别显示为“女童”“中大童”“现货”“源头工厂”“支持打样”。
2. 未配置映射的标签仍会展示原始值。
3. 分类加载失败不阻断商家列表，卡片继续展示原始标签。
4. 不改变筛选请求中的分类代码，也不改变卡片的导航、认领和主页入口。
5. 为中文映射与未知值回退添加自动化测试，并运行拿货档口相关测试。
