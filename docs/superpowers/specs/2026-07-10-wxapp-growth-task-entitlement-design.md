# 小程序成长任务权益页优化设计

## 背景

现有“新手成长权益活动”已经具备活动配置、规则配置、事件触发、权益自动发放和小程序权益页展示能力。当前小程序页面更像“活动说明 + 已到账权益列表”，能告诉用户有哪些规则，但不能清楚表达“我现在该做什么、还差多少、完成后能得到什么”。

本次优化目标是把“新手权益”从说明页升级为任务式成长权益页，让新用户顺着平台核心路径完成登录、发布、审核通过、分享和资源维护。权益仍按现有增长活动规则自动发放，不引入手动领取。

## 目标

1. 用户进入页面后能立即看到下一步建议动作，例如去发布、等待审核、去分享、去使用权益。
2. 任务展示清楚进度、奖励、有效期和状态，降低新用户理解成本。
3. 保留现有增长活动的配置化能力，任务展示从活动规则和业务数据中计算，不在前端写死奖励数值。
4. 区分一次性新手主线任务和每日曝光任务，避免每日发布类任务刺激低质量重复发布。
5. 权益达标后继续自动到账，不做手动领取、积分商城或复杂任务中心。
6. 活动暂停、结束或停用后，前台隐藏未发放任务，已到账权益仍按原有效期展示和使用。

## 非目标

1. 不做“领券中心”的手动领取流程。
2. 不新增积分、等级、连续签到、现金红包或提现。
3. 不把“单纯分享动作”作为奖励条件，分享类任务必须依赖有效浏览或有效联系。
4. 不把所有任务都改成每日任务。
5. 不重构 VIP、次数包和人工发放权益体系。

## 方案选择

采用“新手主线任务 + 每日曝光任务 + 自动到账”的方案。

推荐理由：

- 新手主线任务承担引导职责，帮助用户完成冷启动关键路径，适合一次性完成。
- 每日曝光任务承担活跃职责，鼓励用户维护和传播已发布资源，适合小额、可重复奖励。
- 自动到账减少用户操作阻力，也复用现有 `growth_reward_grants` 和 `merchant_entitlements` 发放闭环。
- 前台只展示状态和下一步动作，不把任务页做成复杂运营系统。

不采用“所有任务每日重置”。发布类任务如果每日刷新，会鼓励用户为了拿奖励重复发布低质量资源，和平台增加真实供给的目标冲突。

不采用“手动领券中心”。手动领取需要新增可领取状态、领取接口、未领取过期和重复领取控制，现阶段收益不如先把新手路径讲清楚。

## 任务分层

### 新手主线任务

主线任务只完成一次，用于引导用户完成核心路径。

| 任务 | 进度口径 | 奖励来源 | 页面动作 |
| --- | --- | --- | --- |
| 首次登录 | 是否已有首次登录发放记录或基础发布权益 | `user_first_login` | 已到账 / 去发布 |
| 发布首条资源 | 商家是否已有资源记录；如已有待审核资源则显示待审核 | 资源发布流程和后续审核事件 | 去发布 / 等待审核 |
| 首条资源审核通过 | 是否已有已发布资源或对应发放记录 | `resource_first_approved` | 去使用权益 |
| 连续优质发布 | 近 30 天已发布资源数 / 规则门槛 | `resource_approved_count_reached` | 去发布 |

主线任务展示时需要优先表达用户当前状态：

- 没有资源：提示“发布首条资源”。
- 有待审核资源：提示“等待审核通过后自动到账”。
- 已达标并到账：提示“已到账，可用于发布或刷新”。
- 活动规则未启用：不展示对应任务。

### 每日曝光任务

每日任务只覆盖曝光和维护行为，每天按自然日计算进度，奖励较小。

| 任务 | 进度口径 | 奖励来源 | 页面动作 |
| --- | --- | --- | --- |
| 分享带来有效联系 | 今日有效电话点击或微信复制次数 / 每日上限 | `resource_share_effective_contact` | 去分享 |
| 分享带来有效浏览 | 当前规则窗口内有效分享浏览数 / 门槛 | `resource_share_effective_view` | 去分享 |
| 维护资源活跃 | 当前阶段仅作为文案预留，不发放权益 | 后续可接刷新事件 | 去管理资源 |

每日任务规则：

- 奖励只发刷新次数等曝光权益，不发大量发布次数。
- 只奖励有效结果，不奖励单纯点击“分享”。
- 自己访问或自己联系自己的资源不计入任务进度。
- 达到规则每日上限后显示“今日已完成”，次日重新计算。

## 页面结构

页面名称继续使用“新手权益”或“成长权益”，不改成纯“领券中心”。

页面从上到下分为四块：

1. 权益余额概览：展示当前发布次数、刷新次数，以及最近到期提示。
2. 新手成长进度：展示主线任务完成数，例如“已完成 2/4”。
3. 新手主线任务：按任务顺序展示进度、奖励、状态和动作按钮。
4. 每日曝光任务：展示今日可做的分享和联系任务，突出“今日”进度。

任务卡片字段：

| 字段 | 说明 |
| --- | --- |
| `taskCode` | 前端稳定渲染键 |
| `title` | 任务名称 |
| `description` | 用户能理解的动作说明 |
| `group` | `starter` 或 `daily` |
| `progressCurrent` | 当前进度 |
| `progressTarget` | 目标进度 |
| `status` | `todo`、`in_progress`、`pending_review`、`completed`、`granted`、`locked` |
| `rewardType` | `publish_quota` 或 `refresh_quota` |
| `rewardAmount` | 奖励数量 |
| `rewardText` | 展示文案，例如“奖励 5 次发布次数” |
| `validDays` | 权益有效天数 |
| `actionType` | `publish`、`share`、`manage_resources`、`use_entitlement`、`none` |
| `actionText` | 按钮文案 |
| `hint` | 补充提示，例如“审核通过后自动到账” |

## 后端接口设计

新增用户侧任务汇总接口，建议路径：

```text
GET /api/v1/merchants/{merchantId}/growth-tasks
```

接口需要用户登录，并校验当前用户可管理该商家。返回活动概览、余额概览和任务列表。

响应示例：

## 数据来源

任务汇总接口只负责读取和组合，不直接发放权益。

核心数据来源：

- 活动和规则：`growth_campaigns`、`growth_campaign_rules`。
- 已到账状态：`growth_reward_grants` 中 `status = 'granted'` 的记录。
- 权益余额：`merchant_entitlements` 中未过期且可用的发布和刷新权益。
- 发布进度：`resources` 中当前商家的资源状态、发布时间和审核通过数量。
- 分享和联系进度：`resource_contact_events` 中 `share_view`、`phone`、`wechat` 等有效行为。

每日任务时间口径使用服务端时区的自然日，查询条件按 `created_at >= date_trunc('day', now())` 计算。涉及规则窗口的任务，例如分享有效浏览，优先使用规则 `conditions.windowHours`。

## 状态规则

任务状态按以下优先级计算：

1. 规则未启用或活动不可见：不返回该任务。
2. 已有对应 `granted` 发放记录且未被撤销：`granted`。
3. 有待审核资源但尚未触发审核通过奖励：`pending_review`。
4. 当前进度大于 0 且小于目标：`in_progress`。
5. 当前进度达到目标但奖励仍在异步处理中：`completed`，提示“权益正在到账中”。
6. 当前进度为 0：`todo`。

由于当前增长权益在业务事件中同步触发，正常情况下达标后应直接进入 `granted`。`completed` 只作为容错状态，避免用户在发放失败或延迟时看到倒退。

## 前端交互

动作按钮规则：

- `publish`：跳转发布页。
- `share`：跳转“我的发布”或资源详情，引导用户分享已发布资源。
- `manage_resources`：跳转“我的发布”。
- `use_entitlement`：跳转发布页或我的发布页，按权益类型决定。
- `none`：不显示主按钮。

页面空态：

- 未登录：引导登录。
- 无商家 ID：提示先登录并创建默认商家资料。
- 无活动：隐藏任务区，只展示已有权益余额。
- 接口失败：提示“成长任务暂时不可用，请稍后重试”，不影响“我的”页其它模块。

## 后台配置约束

后台仍通过增长活动规则配置奖励数值和上限。为了前台能稳定分组，建议在 `conditions` 或前台映射中约定任务分组：

- `per_user_limit = 1` 的发布类规则默认归入新手主线任务。
- `per_user_daily_limit` 或 `per_resource_daily_limit` 存在的分享类规则默认归入每日曝光任务。
- 邀请奖励规则首期仍保持隐藏或 inactive，待邀请归因稳定后再展示。

后续如果运营需要更精细的展示排序、图标和按钮，可在 `conditions` 中增加 `frontendGroup`、`frontendActionType`、`frontendSort` 等字段；本期不强制迁移表结构。

## 风控边界

- 发布类主线任务只看真实资源和审核通过状态，不奖励草稿和被驳回资源。
- 每日曝光任务必须依赖有效浏览或有效联系，不奖励单纯分享动作。
- 自己管理的资源被自己访问、电话解锁或微信复制时，不写入联系事件，也不计入奖励。
- 达到每日上限后不再发新奖励，但页面仍展示“今日已完成”。
- 活动暂停或停用后不展示可继续完成的任务，已到账权益不回收。

## 验收标准

1. 新用户进入“新手权益”页，可以看到主线任务和明确下一步动作。
2. 没有资源时，首要动作是“去发布”。
3. 已提交但未审核通过时，页面显示“等待审核”而不是错误地显示已完成。
4. 首条资源审核通过后，任务显示已到账，并能在权益余额中看到发布次数增加。
5. 分享带来有效联系后，每日曝光任务进度更新，并受每日上限限制。
6. 活动规则停用后，前台不再展示对应任务。
7. 活动停用后，历史已到账权益仍能在余额区展示和使用。
8. 权益任务接口失败时，页面展示友好提示，不暴露数据库、SQL 或内部错误。

## 测试策略

后端测试：

- 任务汇总接口校验登录和商家管理权限。
- 无活动时返回空任务但不报错。
- 主线任务根据资源数量、资源状态和发放记录计算正确状态。
- 连续优质发布任务按规则 `approvedCount` 和 `windowDays` 计算进度。
- 每日曝光任务按今日有效联系和规则上限计算进度。
- 已发放记录优先显示 `granted`，避免重复提示用户继续做已完成任务。

小程序测试：

- 未登录、无活动、无资源、待审核、已到账等状态渲染正常。
- 主线任务和每日任务分区展示。
- 按钮跳转到发布页、我的发布或资源详情路径正确。
- 接口失败时展示中文友好提示。

## 实施边界

第一阶段只做成长任务展示和自动到账状态表达，不做手动领取。后续如果需要加强运营感，可以在已有任务状态基础上增加“可领取”和“领取接口”，但必须重新评估未领取过期、重复领取和召回策略。
