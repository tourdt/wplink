# 小程序首页新入驻商家设计

日期：2026-07-31

## 1. 目标

在首页为刚完成正式入驻的商家提供稳定曝光，形成明确的入驻激励，同时让用户感知平台持续有新商家加入。

本功能不是采购匹配推荐，也不替代“拿货地图”商家目录。首页只展示最多 6 家新入驻商家，完整商家浏览继续由拿货地图承接。

## 2. 已确认规则

1. 首页新增“新入驻商家”区块，位于快捷入口之后、“近期供需”之前。
2. 最多展示 6 家，按正式入驻时间从新到旧排序。
3. “正式入驻”指商家已自主提交并完善公开资料，商家资料处于可公开访问状态。
4. 平台预收录档口、资料未完善账号、停用或删除商家不进入该区块。
5. 首页接口失败或没有符合条件的商家时隐藏整个区块，不阻断 Banner、快捷入口和近期供需。
6. 点击商家卡进入对应商家主页；点击“更多”进入拿货地图的商家列表。

## 3. 正式入驻时间

新增 `merchants.onboarded_at` 字段记录商家首次从资料未完成状态进入资料完成状态的时间。

- 新商家首次完成资料时写入当前时间。
- 后续编辑商家资料不修改该时间，避免商家通过反复编辑重新获得“新入驻”排序。
- 历史上已经完成资料的商家使用 `created_at` 回填，保证升级后首页可以立即展示数据。
- 商家记录创建时间不能直接作为新入驻依据，因为用户首次登录时系统会自动初始化未完成的商家记录。

## 4. 数据资格与排序

首页查询只返回同时满足以下条件的商家：

- `merchants.status = 'active'`；
- `merchants.profile_status = 'completed'`；
- `merchants.deleted_at IS NULL`；
- `merchants.onboarded_at IS NOT NULL`；
- 存在状态为 `active`、角色为 `owner` 的商家管理员绑定，表示商家由用户自主入驻并持有；
- 所属城市站与首页城市一致。

查询按 `onboarded_at DESC, id DESC` 排序并固定限制 6 条。接口不接收前端传入的数量，避免首页展示规则分散到客户端。

## 5. 接口

新增公开接口：

```text
GET /api/v1/home/recent-merchants?cityCode=zhili
```

响应：

```json
{
  "items": [
    {
      "id": "merchant-id",
      "name": "小鹿童装",
      "merchantType": "stall",
      "mainCategories": ["女童", "连衣裙"],
      "logoUrl": "https://example.com/logo.jpg",
      "addressText": "织里童装城 A 区 101",
      "onboardedAt": "2026-07-31T10:00:00Z"
    }
  ]
}
```

接口只返回公开展示字段，不返回联系人、手机号、微信或其他敏感资料。数据库失败时记录城市和固定数量等诊断上下文，向前端返回“新入驻商家加载失败，请稍后重试”。

## 6. 首页展示

“新入驻商家”采用两列卡片网格，最多三行，确保 6 家都能在首页正常滚动区域内获得曝光，不依赖横向滑动才能被发现。

每张卡展示：

- 商家 Logo；无 Logo 时使用商家名称首字作为稳定占位；
- 商家名称；
- “新入驻”标识；
- 商家类型；
- 最多 2 个主营品类；
- 入驻日期，使用“今天入驻”“昨天入驻”或 `MM-DD 入驻`；
- 地址首行；缺少地址时显示“地址资料待完善”。

卡片不展示联系方式、认证、评分、虚构热度或 VIP 信息。点击卡片进入 `/pages/merchant/detail?id=<merchantId>`。

## 7. 异常与降级

- 接口请求失败：前端静默隐藏区块，不弹错误提示，不影响首页其他请求。
- 返回空数组：隐藏区块，不展示空态占位。
- 个别字段缺失：使用商家名称首字、商家类型和地址的安全兜底文案，卡片仍可点击。
- 商家主页在点击后已停用或删除：沿用商家详情页现有的友好错误处理。

## 8. 验证标准

1. 首页最多展示 6 家，顺序与正式入驻时间一致。
2. 资料未完成、停用、删除、预收录或没有有效 owner 绑定的商家不返回。
3. 商家后续编辑资料不会刷新正式入驻时间。
4. 首页卡片可进入商家主页，“更多”可进入拿货地图。
5. 接口失败和空结果不会影响首页其他模块。
6. API 响应不含联系人、手机号和微信。
7. 数据库迁移可升级、可回滚，并通过静态迁移校验。
