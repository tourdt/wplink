# 小程序「我的权益」卡片冷启动优化设计

## 目标

优化小程序「我的」页面中的「我的权益」卡片，使用户先快速看懂发布次数和刷新次数，再被自然引导去完成免费任务。项目结束冷启动阶段后，在不改变用户已熟悉布局的前提下，将主要获取入口平滑切换为付费购买。

本次设计的核心阅读顺序为：

1. 看卡片标题和权益明细入口。
2. 看发布次数和刷新次数余额。
3. 根据余额状态选择免费获取或付费补充。

## 当前问题

现有卡片同时在标题区域展示说明文案、「免费获得」和「查看」，并在余额块中展示购买操作，存在以下问题：

1. 标题、说明和两个操作竞争首屏注意力，中文文案容易换行，阅读节奏不稳定。
2. 「免费获得」「查看」「购买刷新次数」同时使用强调色，用户难以快速判断主操作。
3. 数字、标签和购买按钮垂直堆叠在较窄的双列卡片中，余额为零时显得拥挤。
4. 整张卡片可点击，但卡片内部又有多个独立入口，容易产生误触和跳转预期不一致。
5. 当前设计没有清晰表达冷启动期「免费任务优先」与后续「付费购买优先」的阶段差异。

## 设计方向

采用已确认的 A 方案：余额在前，获取方式在后。

卡片继续使用上下结构：

1. 顶部只展示「我的权益」和「权益明细」。
2. 中部使用两个并列余额块，分别展示可发布次数和可刷新次数。
3. 底部使用整行任务入口，引导用户免费获得更多次数。

该方案保留现有大数字余额的识别优势，同时移除标题行中的操作拥挤。冷启动结束后只需替换底部主入口内容，不需要重做卡片结构。

## 信息结构与文案

### 标题区

- 标题：`我的权益`
- 右侧入口：`权益明细 ›`
- 辅助说明：`剩余次数可用于发布和刷新供需信息`

标题区不再展示「免费获得」和「查看」两个并列入口。

### 余额区

余额块使用用户视角的短标签：

- `可发布` + `{数量} 次`
- `可刷新` + `{数量} 次`

余额充足时，底部使用弱文案 `可正常使用`。数量和单位同一行展示，单位使用较小字号，避免数字与标签之间的语义断裂。

### 免费任务区

余额充足或低余额时：

- 标题：`做任务，免费得次数`
- 说明：`完成任务，奖励自动到账`
- 操作：`去完成`

某项余额为零时：

- 标题：`也可以免费获取`
- 说明：`完成任务，奖励自动到账`
- 操作：`去完成`

标题不再使用「发布优质资源、有效分享可获得更多曝光权益」等较长营销文案，具体任务规则在任务页展示。

## 余额状态规则

| 状态 | 余额块表现 | 付费入口 | 免费任务入口 |
| --- | --- | --- | --- |
| 加载中或加载失败 | 数量显示 `--`，使用中性样式 | 隐藏 | 活动可用时正常展示 |
| 剩余数量大于 2 | 蓝灰色中性余额块，显示「可正常使用」 | 隐藏 | 绿色整行入口 |
| 剩余数量为 1–2 | 浅暖色提醒，显示「即将用完 · 去补充 ›」 | 弱入口，进入对应次数包 | 绿色整行入口 |
| 剩余数量为 0 | 浅橙色不足状态 | 显示「购买发布次数 ›」或「购买刷新次数 ›」 | 改为「也可以免费获取」 |

只有权益接口成功返回且商户身份有效时，才能依据余额展示低余额或零余额购买入口。未知状态不能被当作零余额，避免接口故障时错误引导用户付费。

发布次数和刷新次数分别判断、分别展示状态；一项不足不能影响另一项的正常状态。

## 点击与跳转规则

整张权益卡取消统一点击行为，只有明确的文字入口可以点击：

1. `权益明细 ›`：进入权益明细页，查看余额、到期时间和任务进度。冷启动期复用现有成长权益页。
2. `去完成`：进入成长任务页。
3. `即将用完 · 去补充 ›`：进入对应类型的次数包购买页。
4. `购买发布次数 ›`：直接进入发布次数包购买页。
5. `购买刷新次数 ›`：直接进入刷新次数包购买页。
6. 数字、标签和卡片空白区域不触发跳转。

购买入口继续使用已有路由约定：

- 发布次数：`/pages/vip/index?tab=addons&quotaType=publish_quota`
- 刷新次数：`/pages/vip/index?tab=addons&quotaType=refresh_quota`

## 视觉语义

卡片只使用三组有明确含义的颜色：

1. 蓝灰色：余额、标签和基础信息，保持稳定和中性。
2. 绿色：免费任务及其主操作，建立「绿色等于免费获得」的固定认知。
3. 橙色：仅在低余额或零余额时出现，表示需要补充；零余额状态的强调强于低余额状态。

标题区不再同时出现绿色和橙色文字。购买入口不使用大面积实心胶囊按钮，避免在双列余额块内形成拥挤感；使用清晰的文字入口和浅色状态背景即可。

卡片沿用当前页面圆角和阴影体系，不新增与现有「我的」页面无关的装饰。主要点击入口需保持足够触摸高度，文案较长时优先独占一行，不能挤压余额数字。

## 冷启动阶段切换

### 冷启动期

- 底部整行主入口展示免费任务。
- 余额充足时不展示购买入口。
- 仅在低余额或零余额时，在对应余额块内提供付费补充入口。

### 冷启动结束后

- 保留标题区和双列余额区，避免用户重新学习。
- 底部整行主入口可由运营配置切换为「购买次数包」。
- 免费任务仍存在时，降为权益明细页中的次级入口，不再占用卡片主操作位。

本次只确定前端展示策略，不新增阶段切换后台配置；何时切换及由何种配置驱动，在冷启动结束前另行设计。

## 异常与边界状态

1. 用户未登录时不展示权益卡，保持现有登录态规则。
2. 已登录但尚未绑定有效商户身份时，不展示购买入口；点击需要商户身份的入口时继续使用现有资料完善保护。
3. 权益接口加载中或失败时显示 `--`，不显示低余额或零余额提示。
4. 成长活动接口失败或当前没有有效活动时，隐藏免费任务入口，不显示无法执行的操作。
5. 最近到期提醒继续保留在卡片底部；只有存在七天内到期权益时展示，且不能挤入双列余额块。
6. 发布次数和刷新次数均为零时，两个余额块分别显示对应购买入口，底部仍只保留一个免费任务入口。

## 改动范围

### 包含

1. 调整 `wxapp/pages/my/index.vue` 中权益卡的信息层级、文案、点击区域和状态样式。
2. 保留现有余额加载、低余额判断、购买路由、成长任务路由和最近到期提醒逻辑。
3. 更新 `wxapp/pages/my/index.test.mjs`，覆盖新的文案、状态和点击边界。

### 不包含

1. 不修改权益、成长任务、次数包和支付相关后端接口。
2. 不改变权益发放、扣减、到期或购买规则。
3. 不重做成长任务页或次数包购买页。
4. 不新增冷启动阶段后台配置。
5. 不调整「我的」页面其他卡片和服务入口。

## 验收标准

1. 用户能在进入「我的」页面后直接看到发布次数和刷新次数，标题操作不再换行拥挤。
2. 余额大于 2 时不展示购买入口，免费任务是唯一强调操作。
3. 余额为 1–2 时只在对应余额块显示弱补充入口。
4. 余额为 0 时只在对应余额块显示准确的购买入口，并能直接打开对应次数包。
5. 权益数据未知时显示 `--`，不错误展示购买入口。
6. 整张卡片、数字和空白区域不再触发跳转。
7. 免费任务、权益明细、发布次数购买和刷新次数购买四类入口互不混用。
8. 成长活动不可用时不展示免费任务入口，权益余额仍可正常查看。
9. 最近到期提醒的既有展示逻辑保持不变。
10. 现有登录保护、商户资料保护和次数包购买路由保持可用。

## 测试策略

1. 源码行为测试覆盖标题、辅助文案和免费任务的新文案。
2. 覆盖余额充足、低余额、零余额和未知余额四种状态。
3. 覆盖发布次数与刷新次数独立判断。
4. 断言整张卡片不再绑定统一点击事件。
5. 断言各购买入口携带正确的 `quotaType`。
6. 执行小程序「我的」页面测试和现有流程校验，确认登录、成长任务和购买路径未回归。
