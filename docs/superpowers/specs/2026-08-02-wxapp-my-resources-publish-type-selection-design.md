# 我的发布新建发布类型选择设计

## 背景与目标

“我的发布”页面的悬浮“发布”按钮和空态“继续发布”按钮目前会直接打开 `pages/publish/edit`。新建资源在未选择 `typeCode` 的情况下进入表单，跳过了现有的发布类型选择流程。

本次改动的目标是：用户从“我的发布”新建发布时，必须先选择发布大类和具体发布类型；选择完成后再进入与类型匹配的表单。

## 范围

### 包含

- 调整 `pages/my-resources/index.vue` 的新建发布入口。
- 复用 `pages/publish/index.vue` 已有的“发布大类 → 具体发布类型 → 编辑表单”流程。
- 更新针对“我的发布”新建发布入口的自动化测试。

### 不包含

- 不修改发布类型接口、类目配置或表单动态字段。
- 不改变草稿编辑、驳回后编辑、再发类似的跳转流程。
- 不改变现有发布类型页的界面、登录校验或类型选择逻辑。

## 方案选择

采用复用现有发布类型页的方案。

当用户点击“发布”或“继续发布”时，页面继续先执行已有的商家资料校验；校验成功后使用 `uni.switchTab` 切换至 `pages/publish/index`。该 tab 页已负责登录校验、加载城市发布类型、按大类展示并在需要时打开具体类型选择面板。用户选择具体类型后，页面会携带 `typeCode` 跳转至 `pages/publish/edit`。

不在“我的发布”页面新增选择弹层，避免重复类型加载、分组、登录处理和跳转逻辑。

## 流程

```text
我的发布：发布 / 继续发布
  → 校验登录与当前商家资料
  → 切换至发布类型页
  → 选择发布大类
  → 选择具体发布类型
  → 打开携带 typeCode 的发布编辑页
```

草稿编辑、驳回后编辑与再发类似仍直接进入 `pages/publish/edit`，以保留其既有资源标识、草稿内容或复用内容。

## 错误处理

- 未登录或商家资料未完善时，继续由现有守卫中止流程并引导用户处理，不切换发布类型页。
- 发布类型页加载失败或暂无可用类型时，继续使用该页当前的加载态、空态和刷新操作。

## 验收与测试

- 点击“我的发布”页面的悬浮“发布”或空态“继续发布”，不会直接进入编辑页。
- 完成发布类型选择后，仍由现有逻辑带 `typeCode` 打开编辑页。
- 草稿编辑、驳回后编辑和再发类似仍直接打开编辑页。
- 自动化测试覆盖新建入口的跳转目标与资料校验顺序；运行相关测试及小程序页面/流程校验。
