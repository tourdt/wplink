# 小程序档口位置与周边入驻商家设计

日期：2026-08-01

适用范围：衣货通微信小程序“拿货档口”页面、商家卡片与商家位置地图

## 1. 背景

当前“拿货地图”页面同时提供商家列表和地图找货两种展示方式。采购用户判断一家商家是否值得查看时，主要依赖商家名称、主营品类、档口号、入驻状态和当前供需；地图更适合回答“商家在哪里”和“怎样到店”。

因此，地图不再与商家列表承担同等的找货职责。主页面以档口列表为核心，地图调整为某个商家的位置详情能力。同时保留周边已入驻商家的弱曝光，让用户在确认目标店铺位置时可以顺带发现附近商家，但不改变当前店铺的视觉主次。

## 2. 产品目标

1. 用户可以从商家卡片或商家主页查看该商家的准确地图位置。
2. 地图始终明确突出当前查看的商家，避免用户误认目标店铺。
3. 周边平台入驻商家获得次级曝光，并可通过列表稳定浏览。
4. 地图继续承接到店导航，不承担主要的货源筛选和商家搜索任务。

## 3. 已确认决策

1. “拿货档口”默认使用商家列表，不再把地图作为并列的默认找货方式。
2. 用户点击商家卡片或商家主页中的“查看位置”后，进入该商家的位置地图。
3. 当前商家使用强 Marker，并永久展示商家名称；周边平台商家使用弱 Marker，不永久展示名称。
4. 周边对象只包含平台内已入驻且正常营业、具有有效经纬度的商家，不包含待认领档口。
5. 地图底部提供可展开的“周边已入驻商家”半屏抽屉。
6. 周边查询以当前商家为固定中心，不跟随用户定位，也不因拖动地图自动改变。
7. 用户查看周边商家时，当前商家仍保持地图主目标；进入另一商家主页后，才建立新的查看上下文。
8. 现有一级入口仍使用 `/pages/sourcing-map/index`，页面和 Tab 文案调整为“拿货档口”；商家位置使用独立页面 `/pages/merchant/location`，不在一级页面内部保留地图模式。

## 4. 页面结构

### 4.1 拿货档口列表

现有 `/pages/sourcing-map/index` 调整为“拿货档口”页面，继续承载：

- 商家、档口号和市场关键词搜索。
- 入驻状态和主营品类筛选。
- 商家卡片列表。
- 商家主页入口。
- “查看位置”或“导航到店”入口。

页面不再提供“商家列表｜地图找货”的同级切换。没有可靠经纬度的商家不展示“查看位置”和“导航到店”，改为提示“位置待完善”。

### 4.2 商家位置地图

用户通过 `/pages/merchant/location?merchantId=123` 这类带商家 ID 的地址，从一个确定的商家进入位置地图。页面由以下部分组成：

1. 顶部栏：返回按钮和“商家名称 · 店铺位置”。
2. 地图区：以当前商家经纬度为中心，初始 `scale` 为 16，用户可以继续缩放和拖动查看方位。
3. 当前商家 Marker：品牌强调色、大尺寸、永久名称标签。
4. 周边商家 Marker：灰蓝色、小尺寸、无常驻名称标签。
5. 底部当前商家卡：商家名称、档口地址、主营摘要和“导航到店”。
6. 周边入口：“周边已入驻商家 N 家”，点击后展开半屏列表。

微信原生地图底图自带的道路、建筑和公共地点只作为方位参照；本设计所称“周边商家”均指衣货通平台内商家。

## 5. Marker 视觉与交互

### 5.1 当前商家

- 使用品牌橙色 `#C23A00`。
- 尺寸明显大于周边 Marker。
- 始终展示商家名称标签。
- 页面首次加载时居中展示。
- 打开周边列表或临时选中周边商家后，仍保持强 Marker 状态。

### 5.2 周边商家

- 使用低饱和灰蓝色 `#94A3B8`，尺寸小于当前 Marker。
- 默认不展示名称，减少密集档口区域的遮挡。
- 点击 Marker 后，仅显示轻量名称提示，并同步高亮半屏列表中的对应项。
- 临时选中的周边 Marker 使用深灰蓝色 `#475569`，但不改变为当前商家的尺寸。
- 首期不提供地图拖动后的“搜索此区域”，避免重新演变为地图找货页面。

多个周边商家坐标重叠时，地图允许 Marker 重叠，用户仍可通过周边列表完整访问结果。首期不增加聚合、蜘蛛展开或场内楼层地图。

## 6. 周边商家半屏列表

### 6.1 查询范围

- 以当前商家经纬度为中心。
- 首期固定查询直线距离 1 公里内的商家。
- 仅返回已入驻、正常展示且具有有效经纬度的商家。
- 排除当前商家。
- 按直线距离从近到远排序，最多展示 20 家。
- 不因用户拖动或缩放地图自动重新查询。

### 6.2 折叠状态

底部展示“周边已入驻商家 N 家”。没有周边结果时展示“附近暂无其他入驻商家”，不提供可展开入口。

### 6.3 展开状态

半屏抽屉覆盖地图下半部分，列表项包含：

- 商家名称。
- 主营品类摘要。
- 市场、楼栋、楼层或档口号。
- 与当前商家的直线距离。
- “查看商家”入口。

点击列表项时，地图高亮对应的周边 Marker；点击“查看商家”后进入该商家主页。用户从新商家主页再次点击“查看位置”时，新商家才成为地图的当前商家。

列表首期不增加关键词搜索、品类筛选、排序切换和分页入口。超过 20 家的结果不继续加载，避免把半屏抽屉扩张成第二个商家目录。

## 7. 数据流与职责边界

### 7.1 页面输入

位置地图必须通过 `merchantId` 携带当前商家的唯一标识。页面先读取当前商家详情，确认商家状态和经纬度，再加载周边商家。

### 7.2 当前商家数据

当前商家详情负责提供：

- 商家 ID 和名称。
- 主营摘要。
- 市场、楼栋、楼层、档口号和文字地址。
- 经纬度。
- 营业和公开状态。

### 7.3 周边商家数据

周边查询使用当前商家的经纬度和固定半径，服务端负责过滤入驻状态、公开状态和有效位置，并返回距离。前端负责 Marker 视觉状态、抽屉展开状态和临时选中状态。

若现有接口不能直接按中心点和半径查询，可在实现阶段复用现有商家地图查询能力，用 1 公里外接矩形缩小候选集合，再由服务端计算直线距离和最终过滤。距离计算和结果排序不能只依赖前端，避免不同客户端出现不一致结果。

## 8. 异常与降级

1. 当前商家没有有效经纬度：入口处显示“位置待完善”，不进入地图页。
2. 当前商家详情失效或已下架：地图页显示“该商家暂时无法查看”，提供返回入口。
3. 周边商家加载失败：当前商家 Marker、地址和导航继续可用；周边区域显示“周边商家加载失败，请重试”。
4. 周边没有结果：正常显示当前商家位置，并提示“附近暂无其他入驻商家”。
5. 部分周边商家位置无效：服务端直接排除，不生成 Marker，也不进入列表。
6. 商家位置页不读取用户当前位置，也不申请用户定位授权；地图始终以当前商家为中心。
7. 第三方导航打开失败：保留当前地图页并提示“导航打开失败，请稍后重试”。

## 9. 数据验证

需要记录以下行为，用于判断地图能力是否值得继续维护和强化：

- `location_entry_click`：从商家卡片或主页真实点击“查看位置”。
- `location_view`：位置地图上下文与当前商家坐标加载成功。
- `navigation_click`：真实点击“导航到店”。
- `nearby_drawer_open`：周边商家抽屉从关闭变为展开。
- `nearby_marker_click`：真实点击周边 Marker；不得混记列表选择。
- `nearby_list_item_click`：真实点击周边列表项并临时高亮对应 Marker；不得由 Marker 的内部联动触发。
- `nearby_merchant_click`：从周边列表点击“查看商家”并进入另一商家主页。

以上七种事件在位置页内统一使用 `merchant_location` 来源；Marker、列表项和“查看商家”分别统计，避免入口语义相互污染。

首期重点观察“查看位置 → 导航到店”和“查看位置 → 周边列表项 → 周边商家主页”两条路径，不以地图停留时长作为主要成功指标。

## 10. 验收标准

1. 拿货档口默认展示商家列表，不出现同级地图找货切换。
2. 有效位置的商家可以进入位置地图，无效位置不会产生虚假 Marker 或导航入口。
3. 当前商家 Marker 在颜色、尺寸和名称标签上始终明显强于周边 Marker。
4. 周边 Marker 和半屏列表只包含 1 公里内的其他已入驻商家。
5. 周边列表按距离升序排列，最多 20 家，并与地图 Marker 对应。
6. 点击周边 Marker 可以定位对应列表项，点击列表项可以高亮对应 Marker。
7. 浏览周边商家不会改变最初进入地图的当前商家；进入另一商家主页后才切换业务上下文。
8. 周边接口失败、无结果、位置无效和导航失败均有明确且不阻断主路径的降级反馈。
9. 微信开发者工具和至少一台真机完成地图、抽屉、Marker 点击、商家跳转和导航验收。

## 11. 非本期范围

- 地图区域搜索。
- 地图与商家列表同级切换。
- 周边待认领档口展示。
- 周边商家搜索、筛选和无限加载。
- 推荐算法、广告排序或付费 Marker。
- Marker 聚合和重叠展开算法。
- 市场内部楼层图和室内路线规划。
- 多店串联路线和一键扫街规划。
